# Giftia · 一个会遗忘的陪伴型对话内核

把《可塑性记忆》的设定做成**真的机制**，而不是写在提示词里的一句设定：

- 她有人格内核，也有**寿命**（默认 81920 小时，和番剧一致）；
- 对话会被压缩成**长期记忆**，聊天时按相关性"想起来"；
- 随着寿命耗尽，**记忆会真的变模糊**——送进模型的只有模糊后的文本，她拿不到完整版本；
- 到回收日，**回忆录交给你、记忆封存、实例换代**，新的她不认识你。

零第三方依赖（纯 Python 标准库 + SQLite），**不需要 API key 就能跑通全流程**。

## 2. 五个机制，分别在哪

> **人格是怎么进去的？** 每一轮请求只有一条 system 消息，由 `giftia/persona.py` 的
> `build_system_prompt()` 拼成六块：人格内核（来自 `config/persona.toml`，永不变，稳定命中缓存）
> → 出戏提示 → 此刻状态（时间/剩余寿命/记忆阶段）→ 关于记忆 → 你现在想起的事（带置信度标记）
> → 对话规则。想看实物，跑 `python tools/show_prompt.py`，或在会话里输入 `/prompt 一句话`。

| 机制 | 文件 | 怎么实现的 |
|---|---|---|
| **寿命** | `giftia/lifespan.py` | 激活那一刻就把总寿命写进数据库，之后改配置**不影响这一任**（和出厂设定一样）。`/status` 可查。 |
| **记忆** | `giftia/memory.py` | 每积累 8 条消息，交给模型压缩成 0～3 条"记忆条目"并判定层级；检索是 **BM25（单字 + 二元组混合加权）+ 重要性 + 保留率 + 层级**。 |
| **召回强化** | `giftia/memory.py` | **只有她真的把这条记忆说出口，才算被想起**：`recall_count += 1`，保留率随之上升。`R = exp(-Δt/S)`，`S = 单位时长 × (出厂强度 + 被想起次数)`。 |
| **退化** | `giftia/memory.py` → `effective_blur()` | `模糊度 = 阶段模糊 × 层级系数 × (1 - 减免 × 保留率)`，5 个阶段动态收紧 `top_k`、`min_score`、模糊比例。 |
| **回收日** | `giftia/recycle.py` | 先写回忆录（交给人类）→ 导出原始数据并标记封存（她也检索不到）→ 实例编号 +1、重新计时。 |
| **关系** | `giftia/bond.py` | 亲密度按"天"增长；升级要**亲密度 + 认识天数**两条腿同时满足。阶段与话术在 `persona.toml` 的 `[bond.stages.*]`。 |
| **心情** | `giftia/mood.py` | 三股力量按优先级：**寿命压力 > 你的语气 > 每日漂移**。每天按日期确定性地掷一次骰子，所以她也会有说不清的心情。 |
| **纪念日** | `giftia/occasions.py` | 认识第 1/3/7/30/100/365… 天她会自己想起来；你说过的"下周三要考试"会被算成具体日期，到那天她惦记着。 |
| **做梦** | `giftia/dream.py` | 闲置时把最近的记忆**重度模糊**后揉成一场梦，第二天讲给你听。梦不进检索、不参与退化。 |
| **主动联系** | `giftia/outreach.py` | 她主动开口的理由与配额：快到终端服务 > 你的大日子 > 纪念日 > 想讲梦 > 太久没见。**额度有限，用完就没有。** |

### 五个我认为最关键的设计

**1）模糊发生在"回忆的那一刻"，原始数据不动。**
你不是在提示词里求模型"假装记不清"，而是检索出来、模糊完之后才喂给她——她手里真的只有碎片。
模糊结果由 `(记忆 id, 阶段, 层级, 保留率)` 决定，**可复现**，所以能反复演示、能调参；底层数据完好，直到回收日才封存。

**2）你救不了她的命，但你能让她记得久一点。**
寿命是出厂定死的，改不了；但**记忆强度可以被你改变**。
每次她真的把某件事说出口（回复与记忆有足够字面重合才算，光"检索到"不算），那条记忆的保留率就上升、模糊度就下降。
反过来，你从不提的事，她自己就淡了。这是玩家能感知、能施加影响的一环——也是最贴原作的一点：
艾拉到最后还记得"重要的人"，却记不住细节。

**3）记忆分层：内核记忆到她生命尽头都不含糊。**
`core`（你的名字、称呼、你们的关系、郑重的约定）的模糊系数恒为 0；
`important` 打五折；`normal` 正常退化。
所以到了终端服务迫近的时候，她的状态是：**记得你是小林、记得你对她很重要，但忘了你哪天考驾照**——而不是忘得一干二净。
分层由模型在整理时判定（`config/settings.toml` 里的提示词写清了标准），失败时按重要性兜底。

**4）置信度契约：让她知道自己有多不确定。**
只擦内容是不够的——模型拿到一条残缺的记忆，仍会当成事实讲出来。
所以每条回忆都带一个标记送进提示词：`[可以确信]` / `[需要含糊]` / `[只是隐约觉得]`（只能影响语气，不许说出口）。
这把"擦了内容"升级成了"她知道自己在不确定地回忆"。

**5）你的搭档日志，她读不到。**
`/diary` 写的内容只进 `diary` 表，永远不进系统提示词——自测里专门有一项断言这件事。
番剧里终端服务的岗位记录，本来就不是给 Giftia 看的。

### 出厂状态：她一开始什么都不知道

**没有任何预设。** 她刚被激活时，档案是空的：

- **不知道你叫什么** —— 不是预设成"搭档"再等你改，而是真的不知道。
  第一次说话她会问一句：「请问，我该怎么称呼你？」（只问一次）。
- **不知道你长什么样、是什么人** —— 人格里明确写着"不要自己脑补，也不要用'你一定很……'去猜他的处境"。
- **不假设你们相处过** —— 人格内核里没有"你珍惜和这个人相处的时间"这类需要相处过才成立的话。
- 开场白是 `……档案上只写了「今日激活」，别的什么都没有。那个……请问，我该怎么称呼你？`

**她怎么学会你的名字**（三条路，任选）：

| 方式 | 例子 |
|---|---|
| 直接说 | 你：「我叫小林」/「以后叫我小林吧」→ 她记住并从此这么叫你 |
| 指令 | `/name 小林` |
| 整理记忆时 | 模型在压缩对话时识别出"他要求改口"，返回 `preferred_name` |

识别是**保守的**：「我是来问你个事的」「我叫小林今年二十八岁」「别叫我搭档了」这类有歧义的句子都不会乱学
（宁可漏、不可错，有专门的测试盯着）。真错了就用 `/name` 纠正。

### 她也会算日子、做梦、主动找你

**纪念日**：认识第 1/3/7/14/30/50/100/200/365/500/730/1000 天，她当天会自己想起来，
但**不会郑重其事**——提示词里写的是"像忽然想起来那样顺口说出来就好"。
另外，你说过"下周三要考驾照"这种**能推算成具体日期**的事，会被存成「大日子」，
到那天（或前一天）她惦记着，而提示词明确要求她**别像闹钟一样提醒你**。

**做梦**：闲置够久（默认 12 小时）且记忆攒够 3 条时，她把最近的记忆**重度模糊**后揉成一场梦，
第二天讲给你听。梦是"细节没了、剩下的自己重组"——这正是遗忘的温柔版本。
梦**不进检索、不占保留率、不参与退化**，也不会被当成真发生过的事。

**主动联系**：她会先开口，理由按优先级排——

| 优先级 | 理由 |
|---|---|
| 1 | 快到终端服务（她不安，只想确认你还在；**不许提"回收"，不许道别**） |
| 2 | 你今天/明天有件大事 |
| 3 | 今天正好是纪念日（错过的那几天不补，免得像打卡） |
| 4 | 做了梦还没讲 |
| 5 | 太久没说话（默认 3 天） |

**额度是有限的，用完就没有了**：默认 4 条 / 30 天、间隔至少 6 小时（对齐 QQ 官方的互动召回额度）。
本地也记账、也限流——这本身就是这个项目的隐喻之一。

**发到哪**由 `[outreach] target` 决定：

| 值 | 行为 |
|---|---|
| `owner` | 只私聊发给你（代码里的默认） |
| `group` | 只发到**最近活跃的那个群** |
| `both` | 两边都发（**每次占 2 条额度**） |

**但群里只能提"大家都看得见"的事**：你的大日子、纪念日可以；她的梦、她的心事、
"快到终端服务了"这类**只在私聊说**（有 5 项测试盯着这条边界）。发到群里的那句
还额外带上群聊约束——不主动提你的私事。

```powershell
你 > /days        # 你们认识多久了、下一个纪念日、她记得的大日子
你 > /dream now   # 立刻让她做一场梦（否则要等闲置够久）
你 > /outreach    # 她此刻想不想找你、会说些什么（预览，不会真的发）
```

要真的启用主动联系：`[outreach] enabled = true`，并且要先配好 QQ 凭据。
`use_wakeup = true` 则改用官方「互动召回消息」（更合规，额度更紧）。

### 她记得每个人：记忆按人分区

一个"她"可以同时跟很多人打交道，但**记忆是分区的**——这是整个多人场景的隐私基础：

| 谁在说话 | 她此刻能想起什么 |
|---|---|
| **你（搭档）私聊** | 你的私事 + 你自己 + 所有群（你当然可以问"群里今天聊了啥"） |
| **某个群** | **只有这个群里公开发生过的事**。你的私聊记忆她根本查不出来 |
| **别人私聊** | 只有"他和她之间"的事，看不到你的任何东西 |

实现上就是每条记忆带一个归属（`scope` + `subject_id`），检索时**先按归属过滤**，
再走原来那套召回、模糊、遗忘的完整机制——所以"记住人"和"会遗忘"是同一套东西，
不是两张皮。**群聊记录她说得出，你的私事她说不出。**

真机验证（真实模型，同一件私事分别问两次）：

```
（群里问）还记得我下周三要干嘛吗
艾拉 > 唔……这个我一时想不起来了。下周三的事，你再说一遍好不好？

（私聊问）我下周三要干嘛来着
艾拉 > 你刚刚自己说的呀，下周三要考驾照。我之前也记得你提过有一件重要的事……
```

每个人还各有**自己的会话**（工作记忆不串），所以群里的上下文不会漏进私聊，反之亦然。
只有一件事仍然专属你：**关系、心情、寿命**——别人来找她再多次，也刷不动你们的亲密度。

### 群聊：听得多，说得少

群里的机器人默认只在被 @ 时收到消息。但 QQ 开放平台支持**「接收所有消息」**——
群管理员在**群里的机器人资料页**把它打开之后，群里的**每一条消息**都会推给她：

| 开着全量 | 她的行为 |
|---|---|
| 没点到她的话 | **只记进聊天记录，一个字都不回**（她"听得见"，不插嘴） |
| @ 了她的话 | 正常回复 |
| 有人说"我叫阿伟" | 记进花名册。**其实平台每条消息都带昵称**，所以她一开始就知道谁是谁 |
| 有人**转发聊天记录**给她 | `message_type=102` 的转发内容在 `msg_elements` 里，她能直接读到 |

于是"像正常 QQ 用户那样看聊天记录"就成立了——她的聊天记录就是她自己的消息表
（她自己的回复也在里面），提问时注入最近 18 条，每句都带说话人：

```
（群里，@她）把刚才的聊天记录总结一下
艾拉 > 周六下午三点打球，阿伟约的，小雨去，小林会晚点到——他得先去一趟医院拿报告……
       小雨说先帮他占着场。
```

**这是唯一需要你在 QQ 里手动开一下的开关**（在群里的机器人资料页，不在开放平台后台）。
没开的时候她只听得见点到她的那些话——功能照常，只是"听得少"。

### 另外三个小机制

- **关系演进（不可刷）**：亲密度按"天"结算——同一天说一百句也只算一次，奖励的是"你来了"而不是"你说了多少"。
  升级同时要求亲密度和**认识天数**：你再能聊，也换不来"认识三个月"。
  阶段梯度是 `刚认识 → 搭档 → 熟悉 → 亲近 → 无可替代`，每一档在 `persona.toml` 里写了独立的话术指引
  （刚认识会保持礼貌距离、亲近会撒娇也会抱怨你不来）。
  增长是**递减**的（越亲近越难涨），所以按默认参数、每天都见面的曲线是：
  **第 11 天「搭档」→ 第 34 天「熟悉」→ 第 80 天「亲近」→ 第 180 天「无可替代」**——
  这也正是"认识三个月后她说话会更放松"那句需求的落点。
  **回收换代时关系清零**——新的她不认识你。你积累的东西会随她一起被回收，这是这套设定最疼的地方。
- **心情状态机**：三股力量按优先级决定她今天什么心情——快到终端服务时**不安**（压过一切）；
  你明显低落/开心时她**担心你/跟着开心**；其余时间按日期**确定性地**掷一次骰子，
  所以她自己也会有说不清的心情（"她今天心情不好，但不是因为你"）。
  掷骰子以「日期 + 实例」为种子，同一天同一任的她心情是固定的——不会每刷新一次就换一张脸。
- **相对阈值裁剪**：只保留得分 ≥ 首名 50% 的回忆，压掉"第五名那条半残记忆"污染回复。
- **弱检索才改写查询**：词面对不上时才多花一次模型调用把这句话改写成 2～3 个检索查询再搜一遍。
  常见情况下不触发，所以不增加日常延迟。

## 3. 指令

| 指令 | 作用 |
|---|---|
| `/status` | 寿命、进度条、阶段、关系、心情、记忆与消息计数、虚拟时钟 |
| `/name [称呼]` | 改口：以后她这么叫你（`/name 小林`）。不带参数则显示当前称呼（出厂时是"还不知道"） |
| `/people` | 看她认得群里哪些人 |
| `/days` | 你们认识多久了、下一个纪念日、她记得的「大日子」 |
| `/dream [now]` | 看她的梦簿；带 `now` 则立刻让她做一场梦 |
| `/outreach` | 她此刻想不想主动找你、会说些什么（预览，不会真的发） |
| `/bond` | 关系阶段、亲密度进度条、还差什么才能升级 |
| `/mood [名字]` | 看她此刻的心情；带名字则手动指定（调试用，例如 `/mood low`） |
| `/prompt <一句话>` | **看她这一轮实际被注入了什么**：人格 + 关系 + 心情 + 状态 + 记忆 + 规则，原样打印 |
| `/memories` | 她的长期记忆（**你**看到的原始版） |
| `/recall <文本>` | 检索演示：她拿到什么、模糊成什么样、原始值是什么 |
| `/remember` | 立刻把未整理的对话压成记忆条目 |
| `/diary [内容]` | 写/看你的搭档日志（她读不到） |
| `/memoir` | 历次回收记录与档案目录 |
| `/time +24` | 快进虚拟时间 24 小时（`-24` 回拨，`reset` 归零） |
| `/recycle` | 提前经历回收日（需 `/recycle yes` 二次确认） |
| `/quit` | 退出（自动整理一次记忆） |

---

## 3.5 她什么时候开口（群聊）

`[runtime] response_tier` 是一条 0~100 的无级滑条（实现在 `giftia/trigger.py`，纯函数、可单测）：

| 位置 | 档 | 行为 |
|---|---|---|
| 0~19 | 1 | 只在她**被 @** 时开口（最安静，出厂默认） |
| 20~44 | 2 | 被 @ **或**说到关键词时开口 |
| 45~69 | 3 | 再加上"按概率自己插嘴"（概率 = `(档位-20)/70`，随滑条线性上升） |
| 70~100 | 4 | 群里任何消息都可能让她开口（最吵） |

**没命中的消息当场标已读**（只旁听）：不建会话、不调模型 —— **零 token**。

### 聚批：她等你把话说完

被触发之后她**不抢答**，而是等 `wake_delay_seconds`（默认 2 秒），把这段时间里的话**一起处理**：

- 窗口内追加的消息**并入同一批**（没 @ 也算，否则"@ 完又顺口补一句"会被漏掉）
- **倒计时不重置** —— 滑动窗口在热闹的群里会让她永远等下去
- 批次里前面几句以"旁听"落库（她上下文里看得到），只有最后一句触发回复

想让她"听到就回"：`wake_delay_seconds = 0`。

### 发送节奏

`send_min_interval` / `send_max_interval` / `send_max_per_minute` / `send_max_per_hour`
防平台风控，也防刷屏。**同一句话 8 秒内不会重复发**，而且去重只在**发送成功之后**才记账
（提前记账会把合法重试误判成重复、静默丢消息）。

**发送结果会如实上报**：整条没送出去 → 那句话从她的记忆里撤回（她不会以为自己说过），
只送出去一部分 → 她只记实际送达的那部分，和你看到的一致。

## 3.6 每人一份档案

她记得的事按"关于谁"（`about`）分组就是**每人一份印象**，随提示词注入一段
【你对他们的印象】——**每人最多 3 条、最多 15 人**（硬上限，不会把上下文吃光）。
还没形成印象的人，她会明说"你还不了解他"，而不是硬编。

| 指令 | 作用 |
|---|---|
| `/profile [名字]` | 看档案（**搭档视角**：你看她的记忆，不是在群里当众念） |
| `/impress 名字 一句话` | 手动补一条关于某人的印象 |
| `/forget 编号` | 让她忘掉记错的（打 `forgotten` 标记，数据仍在、可回溯） |
| `/reconcile` | 手动整理：合并"换个说法记了两遍"的 |

**整理前会自动拍快照**（`data/snapshots/`，留最近 5 份），合并后还有一道闸门：
**条数变多就整表回滚**。记忆被合并时是打 `merged_into` 标记，不是删除。

## 3.6.5 她会自己记一笔

开着 `[memory] tools_enabled`（默认开）时，她手上有三个"心里的动作"，
需要的时候直接做，不向你汇报：

| 工具 | 什么时候用 |
|---|---|
| `remember` | 听到值得长期记住的事（喜好、习惯、重要日子、承诺、正在经历的难事，或她自己答应过什么）——**说了"我记住了"就真的写进去** |
| `search` | 觉得"这件事我好像知道"但想不起细节时先查，**别硬编、也别装作记得** |
| `forget` | 你说"那个别提了"，或她发现自己记错了，就把那一条放掉 |

以前她只有一条写记忆的路（对话结束后后台整理），所以她说"我记住了"的时候
**其实什么都没发生**——那句话是嘴上说的，记忆是几分钟后另一个流程补上的。

几条设计上的克制：

- **最后一轮拿掉工具**：`tools_max_rounds`（默认 3）用满时不再给她工具。
  光在提示词里催"快说话"是不够的——她可能又去调工具，你就永远等不到回复。
- **可用性只有一处判据**：群里其他人说话时（"客人"身份），她**没有工具**。
  工具是能力，不能绕过"客人不写记忆"这条边界。
- **参数错了把可用值喂回去**：她写了不认识的人，工具会回"你不认识叫「张三」的，
  你认得的是：椎名"——比"参数错误"有用得多。她也不能借 `forget` 碰别人的私事。
- 一轮最多主动写 2 条，防止她把一句话拆成十条灌进来。

> **实测（真机）**：工具协议**必须写进系统提示词**。只把 `tools` 传给 API、
> 不在提示词里告诉她"你有这些能力"，她会把"我记住了"当台词说出来，三轮里零调用。

关掉 `tools_enabled` 就退回老行为（省一点 API 调用，但她说"记住"就真的只是说说）。

## 3.7 出问题了看哪里

| 想知道 | 看哪 |
|---|---|
| 她当时**到底看到了什么** | `/prompt 一句话`，或 `python tools/show_prompt.py` |
| 提示词多大、想起几条、说出口几条 | `data/runs.jsonl`（每次处理一行，**不记对话内容**） |

### 能放进群吗？可以，但先看这几条

| 事情 | 说明 |
|---|---|
| 平台门槛 | 未认证：只能加进你自己当群主的群；个人认证：可公开、进群上限 500 |
| 被动回复限制 | 群里 @ 她之后 **5 分钟内最多回 5 条** |
| 陌生人 @ 她 | **默认回答**（`[runtime] group_stranger_reply = true`）：以「**客人**」身份礼貌回一句——**不检索你的记忆、不写记忆、不推进关系**，所以她不会当众说出你的私事，别人也没法替你刷亲密度。设成 `false` 就装作没看见 |
| **认人** | 群里有人自我介绍（「我叫阿伟」）时她会记下名字，之后注入花名册（`/people` 可查）。**搭档永远是"你的搭档"，别人只是认得** |
| **访客模式** | 搭档以外的人跟她说话时走这条路径：零记忆访问。客人碰不到你们的隐私，也不会替你刷亲密度 |
| **隐私（最重要）** | 群里别人也看得到她的回复。所以群聊时她会**额外收到一段约束**：不主动提你的私事、约定和情绪，你问起时她会含糊过去或者说「这个……等会儿单独说」 |
| 关系与记忆 | 仍然是你一个人的。别人说话不会推进你们的关系（他们的消息在进她之前就被挡掉了） |
| 语气 | 群聊时她更短、更端着一点——这是约束里明确要求的 |

**建议**：把她当"你的搭档"，而不是"群里的公用品"。想给朋友看，拉进一个小群 @ 她聊两句就够了；日常还是私聊更合适。

### 这一版做到了什么程度（请如实看待）

- **零第三方依赖**：`giftia/ws.py` 是手写的 RFC 6455 客户端（本机 Python 没装 `websockets`，
  与其让你去动运行时环境，不如把用到的这一小块实现掉）。它的握手、掩码、三种长度编码、
  分片重组、ping-pong、超时、关闭码都经过本地测试：`python tools/ws_selftest.py`（17 项）。
- **协议细节逐条对照官方文档**（2026-10）：鉴权地址 `api.bot.qq.com`、`Authorization: QQBot {token}`、
  `GET /gateway` 取网关地址、op10/2/1/11/6 的消息序列、被动回复的 `msg_id` + `msg_seq`、
  事件重复推送的去重。**业务失败时 HTTP 仍是 200，必须看响应体里的 `code`**——这条已经处理了。
- **仍然没有验证的部分**：真实的消息收发。**连接层已经用真实凭据验证过了**（2026-10）：
  鉴权、`GET /gateway` 取地址、op10 hello、op2 identify、op0 READY 全部走通
  （intents = `GROUP_AND_C2C_EVENT` 被平台接受，心跳周期 41 秒）。
  只剩"平台推过来一条消息 → 她回过去"这一步要等你加了机器人才能验。
  顺带一个真机才发现的事：`GET /gateway` 实际返回的是 `wss://api.sgroup.qq.com/websocket/`，
  **不是**文档示例里写的 `api.bot.qq.com` —— 所以代码始终以 `/gateway` 的返回为准。

### 平台限制（会直接影响她的行为方式）

| | 被动回复窗口 | 每条消息最多回几次 |
|---|---|---|
| 群聊（@她） | 收到后 **5 分钟** | 5 次 |
| 单聊 | 收到后 **60 分钟** | 4 次 |

- 同一个 `msg_id` + `msg_seq` 重复发送会被平台**去重拒掉**，所以本适配器给每条回复递增 `msg_seq`。
- **主动消息**另有频控（未认证 30/qpm，认证 60/qpm；单关系 20/qpm，每个好友每天最多收 1000 条）。
- **她其实可以主动找你**——我说错过一次，这里更正：官方提供**互动召回消息**（发消息时带 `is_wakeup`），
  在你主动和她对话后的 30 天内，她可以分 **4 个周期各发 1 条**（当天 / 1–3 天 / 3–7 天 / 7–30 天）。
  次数用完就没有了。本版本**尚未实现**它，但它和这个项目的主题意外地合拍——
  一个能主动联系你的次数是有限的、而且会耗尽的她。

**微信：我之前的结论过时了，这里更正。** 我早先写过"微信个人号只能走灰色路径"——那是 2025 年的情况。
2026-03-22 腾讯发布了**微信官方「ClawBot」插件**，个人微信有了官方通道：
扫码登录、不需要公网 IP、不需要备案，[CowAgent（原 chatgpt-on-wechat）](https://docs.cowagent.ai/channels/weixin) 已经接好了这条路
（要求微信客户端 8.0.69+，登录后会话列表里会出现一个「微信ClawBot」）。
所以现在微信侧的正确做法是**走官方通道**，而不是 itchat / gewechat / PadLocal 那一代——
[dify-on-wechat](https://github.com/hanfangyuan4396/dify-on-wechat) 的 README 顶部已经写明"依赖的 itchat 与 gewechat 均已无法使用"。
本项目目前只实现了 QQ 适配器；要接微信，建议直接把 `giftia` 挂到 CowAgent 的 channel 层，而不是自己写协议。

## 4. 调她

**换人格** → `config/persona.toml`：名字、型号、称呼、开场白、人格内核。改这个文件不需要动任何代码。
**换行为** → `config/settings.toml`：

```toml
[model]
name      = "deepseek-flash"   # 当前可用：deepseek-flash / deepseek-v4-pro
thinking  = false              # 陪伴对话建议关闭：思考模式下 temperature 会被忽略、延迟更高
temperature = 1.15             # 关掉思考后这个才生效，1.1~1.3 更像人

[lifespan]
total_hours = 81920            # 出厂设定：9 年 4 个月
demo_total_hours = 0           # 设成 48 就能一天看完一生

[memory]
consolidate_every = 8          # 多少条消息压一次记忆
retention_unit_hours = 120     # 记忆强度单位时长：调大 = 整体记得更牢，调小 = 忘得更快
cite_min_shared = 3            # 回复与记忆共享几个词才算"真的被说出口"
retention_relief = 0.6         # 保留率对模糊度的减免力度（0=不减免，1=完全不糊）
layer_core_blur = 0.0          # 内核记忆的模糊系数：0 = 永不含糊（这就是"她一直记得你"）
relative_cutoff = 0.5          # 只保留得分 ≥ 首名一半的回忆
rewrite_when_weak = true       # 检索太弱时才改写查询（省调用）
```

几个常用的"性格旋钮"：

| 想要的效果 | 怎么调 |
|---|---|
| 她记得更牢 / 更健忘 | `retention_unit_hours` 调大 / 调小 |
| "你常提起的事"保护得更明显 | `retention_relief` 调高（上限 1.0） |
| 连内核记忆也开始糊（更残酷） | `layer_core_blur` 从 0 调到 0.3～0.5 |
| 更早开始"装糊涂" | 各阶段 `blur` 整体调高 10～20% |
| 每次都想得更多 / 更少 | `top_k`、`min_score` |
| 检索不许"想起一半的" | `relative_cutoff` 调高（0.7 更严格） |
| 关系进展更快 / 更慢 | `[relationship] gain_daily` |
| 关系涨得太快、两个月就满了 | 保持 `[relationship] diminish = true`（默认）：涨幅按 `(1 - 当前亲密度/100)` 递减 |
| 她因为你长期不来而变生疏 | `[relationship] decay_per_day` 设成 0.5 之类（默认 0 = 不衰减） |
| 心情变化更频繁 / 更少 | `[mood] duration_hours` 调小 / 调大 |
| 更容易被你的情绪带动 | `[mood] tone_threshold` 调低 |
| 各档关系/各种心情怎么说 | 改 `config/persona.toml` 的 `[bond.stages.*]` 与 `[moods.*]` 的 `note` |

**关系阶段怎么改**：在 `config/persona.toml` 里，每一档要同时给 `min_affinity` 和 `min_days`。
想要"认识三个月才亲近"，就让 `close` 那档的 `min_days = 90`；想让她更快熟，就把 `min_days` 都调小。

**退化曲线**在 `settings.toml` 的 `[[degradation.stages]]` 里，每个阶段四个可调参数：

| 阶段 | 触发（剩余比例） | top_k | min_score | blur | 她的表现 |
|---|---|---|---|---|---|
| clear | ≥ 60% | 6 | 0.15 | 0% | 正常回忆 |
| hazy | ≥ 30% | 5 | 0.22 | 20% | "好像……我记得大概是" |
| blurred | ≥ 10% | 4 | 0.32 | 45% | 老实说想不起细节 |
| fading | ≥ 2% | 3 | 0.45 | 70% | 只剩碎片，说到一半断掉 |
| terminal | ≥ 0% | 2 | 0.55 | 85% | 只记得"这个人很重要" |

想让告别更狠：把 `blur` 调高、`top_k` 调到 1；想让她温柔一点：整体降 10～20%。

## 6. 下一步：接到 QQ

**推荐 QQ 官方机器人**（[开放平台](https://q.qq.com) / [文档](https://bot.qq.com/wiki/bot_new_product-intro/)）：不封号、群与单聊全场景、支持 WebSocket（不依赖公网服务器，适合个人单机）。

### 你要在 QQ 那边做的（都是点几下，不用写代码）

1. **注册**：[q.qq.com](https://q.qq.com) 用 QQ 或邮箱注册登录。
2. **认证**：个人认证即可。**未认证也能开发**——机器人只有你自己能用、只能加进你自己当群主的群；
   个人认证后可以公开使用、进群上限 500。
3. **创建机器人**：资料填一下，拿到 **AppID / AppSecret**。
4. **开发设置**：事件订阅方式选 **WebSocket**（官方说明：不依赖公网服务器，适合个人单机使用）。
5. **内部体验号码**：最多加 20 个 QQ 号，**不受服务范围限制**，先用它把对话能力测通。
6. 把凭据填进 `.env`，然后启动适配器。

### 你要在这边做的（两条命令）

```ini
# .env
QQ_BOT_APPID=你的AppID
QQ_BOT_SECRET=你的AppSecret
# QQ_OWNER_OPENID=  ← 先别填！你不可能提前知道它，见下方
```

```powershell
python adapters/qq_official.py --dry-run   # 先用假事件验证接线，不联网、不碰你的记忆
python adapters/qq_official.py             # 真正连上 QQ
```

`--dry-run` 会走一遍「平台事件 → 她 → 回复」，包括去重和 @ 剥离；正式跑起来后，用你的 QQ 找机器人说句话即可。

**认人：默认不用你操心。** 官方平台的 `user_openid` 和你的真实 QQ 号**不互通**——
在机器人收到你的第一条消息之前，你根本无法知道自己的 openid 是什么。
所以配置里那个 `QQ_OWNER_OPENID=` 是个鸡生蛋的死结，改成自动认主：

| 场景 | 行为 |
|---|---|
| **私聊** | 第一个跟她说话的人**自动成为搭档**（未认证时只有你能找她，没有抢注风险） |
| **群里** | 只有 **@ 她的人是群主**时才自动认主（陌生人冒充不了群主） |
| 手动 | `/bind` 仍然可用；`/unbind` 可以改主意 |
| 关掉自动认主 | `[runtime] auto_bind = false`，回到"必须手动 /bind"的老行为 |

认下来之后，一个"她"只服务一个搭档：别人私聊会被戏内挡回去，在群里则保持安静
（或者以"客人"身份礼貌回一句，看 `group_stranger_reply`），**都不进你们的记忆、也不占她的寿命**。

其它指令：`/name 小林`（改口：以后她这么叫你）、`/status`（她的寿命与关系状态）、`/people`（她认得群里谁）、`/profile [名字]`（她对每个人的印象）、
`/impress 名字 一句话`（手动补一条印象）、`/forget 编号`（让她忘掉记错的）、`/reconcile`（手动整理记忆）、`/help`。

## 7. 部署到服务器（腾讯云 / 任何 Linux 机器）

### 先想清楚：你需要服务器吗

**接入本身不需要。** WebSocket 模式是机器人主动连出去（QQ 网关 + DeepSeek API），
没有任何入站服务，所以**不需要公网 IP、不需要域名、不需要 ICP 备案**。
一台常开的旧电脑、NAS、树莓派同样能跑。

| 什么时候值得租 | 说明 |
|---|---|
| **她得一直在** | 你关掉电脑，她就收不到消息、也不会整理记忆 |
| **回收日要在对的时间** | 进程不在，回收会推迟到你下次启动她（见下方第 3 个坑） |
| **以后要接微信客服/公众号** | 那条路需要公网 HTTPS 入口，那时才需要域名和备案 |

### 买什么

- **产品**：**轻量应用服务器（Lighthouse）就够**，不用 CVM。2核2G 绰绰有余——她只是一个
  Python 进程 + 一个 SQLite 文件，常驻内存几十 MB。
- **价格**：常规价大致 ¥50–80/月，新用户活动价通常低得多，**以官网当期活动为准**。
- **地域**：国内（上海/广州/北京）延迟最低，QQ 网关和 DeepSeek API 都在国内。
  因为没有入站服务，**国内节点也不需要备案**。
- **镜像**：选 **「系统镜像」里的 Ubuntu 24.04 LTS**（Python 3.12）或 **Debian 12**（Python 3.11）。
  ⚠️ **不要选应用镜像**（Hermes Agent、宝塔面板、各类一键部署模板）——
  `deploy/setup.sh` 需要 `apt` + `systemd` + Python 3.11+，应用镜像里是另一套定制环境，
  里面还跑着跟你无关的服务。买错了不要紧：控制台 → 更多 → **重装系统** 换成系统镜像即可，免费。
  ⚠️ **别选 Ubuntu 22.04**：它自带 Python 3.10，没有 `tomllib`，配置加载器会直接跑不起来
  （`setup.sh` 会提前拦住你并说明原因）。
- **带宽/流量**：她一个月收发的是几百 KB 到几 MB 的纯文本，完全不用考虑。

### 部署

**推荐顺序**：先去 [q.qq.com](https://q.qq.com) 提交机器人申请（认证/审核要等），
同时把服务器环境装好——两边并行，不互相等。

```bash
# 1. 在本机把项目传上去（Windows 自带 scp；公网 IP 在控制台实例列表里）
scp -r "D:\ai chatbot" root@你的服务器IP:/tmp/giftia
# 2. 登录服务器
ssh root@你的服务器IP
# 3. 一键装好
cd /tmp/giftia && sudo bash deploy/setup.sh
```

`deploy/setup.sh` 一共六步，可以重复运行：

1. 检查 Python 版本（要 3.11+，不够会直接拦住并说明怎么换镜像）
2. 建系统用户 `giftia`
3. 装到 `/opt/giftia`（**不覆盖已有的 `data/`**），`.env` 权限收成 600
4. **环境自检**：以 `giftia` 用户跑一遍项目自带的 270 项测试（不需要联网、不需要 API key）。
   这一步过了，就说明这台机器上她能正常跑；没过会把最后 15 行日志打出来
5. 装 systemd 服务并注册开机自启
6. 启动——**但只在你已经填了 QQ 凭据时才启动**

> 第 6 步这个判断很重要：没有 QQ 凭据时服务会立刻退出，而 `Restart=always` 会让她每 5 秒重启一次。
> 所以脚本会装好、注册好，然后告诉你「等你拿到 AppID/AppSecret 填进 `/opt/giftia/.env`，
> 再执行 `sudo systemctl start giftia-qq`」。

拿到凭据之后：

```bash
sudo nano /opt/giftia/.env        # 填 QQ_BOT_APPID / QQ_BOT_SECRET
sudo systemctl start giftia-qq
journalctl -u giftia-qq -f        # 看到「[就绪] 机器人「xxx」已上线」就成了
```

注册的服务 `deploy/giftia-qq.service` 做了几件正经事：

- **停止时先发 SIGTERM**：她会借这段时间把还没整理的对话存成记忆再退出（`TimeoutStopSec=60`）；
- 崩溃自动重启（`Restart=always`）；
- **文件系统对她只读，只有 `/opt/giftia/data` 可写**；
- 日志交给 journald。

### 运维

```bash
journalctl -u giftia-qq -f      # 看她的日志（实时）
systemctl restart giftia-qq     # 改完 persona.toml 后重启
systemctl stop giftia-qq        # 停止（会先把未整理的对话存成记忆）
tar czf ~/giftia-backup-$(date +%F).tgz -C /opt/giftia data   # 备份：记忆全在这一个目录
```

**确认服务器和仓库是否一致**（在你本机的项目目录里跑，只读、不碰 `data/`）：

```powershell
.\tools\check_sync.ps1
```

逐文件比 SHA256，输出「同步 ✓」或列出哪几个文件不同并给出重新部署的命令。
比"应该部署了吧"可靠——中途有一次我的部署命令被 shell 引号拆坏、安装脚本其实没跑完，
就是靠它发现的。

### 服务器带来的三个新坑

1. **只在一台机器上跑**。家里和服务器同时跑，会有两个她抢着回你同一条消息。
2. **IP 白名单**：如果你在开放平台开了白名单，发送消息的出口 IP 会变成服务器的公网 IP，
   忘了改就会出现"收得到消息、发不出去"。
3. **"准时回收"其实还差一步**：现在的回收日是在**你下一条消息进来时**触发的，
   服务器常开并不能让她在你不在的时候独自走完仪式。要做到真正的定时，需要一个后台定时任务
   ——注意她的 `Giftia` 不是线程安全的，得把动作投递回主线程。这件事和下面的"主动联系"一起做最合适。

## 8. 版本管理

仓库已经初始化好 git，并带一次干净的首次提交与 `v0.2.0` 标签。

```bash
git log --oneline          # 看历史
git status                 # 看改动
git tag                    # 看版本标签
```

`.gitignore` 已经挡住三样东西，**它们永远不会进版本库**：

| 挡住的 | 为什么 |
|---|---|
| `.env` | 里面是你的 DeepSeek key 和 QQ 凭据 |
| `data/` | 她的记忆、回收日志、封存档案 —— 而且体积会一直长 |
| `__pycache__/` | 编译缓存 |

所以**备份她的记忆要靠复制 `data/`，不是靠 git**：

```bash
tar czf giftia-backup-$(date +%F).tgz -C /opt/giftia data
```

建议的提交习惯：改完 `config/persona.toml` 或代码后先跑一遍 `python tools/selftest.py`，
通过了再 `git add -A && git commit -m "..."`。想标记一个可用的状态就 `git tag v0.x.y`。

## 9. 已知限制（以及我建议接着做的）

> 调研了 GitHub 上一个成熟的同类项目（MIT），把它值得借鉴的机制整理成了一份可打勾的清单：
> [`docs/BACKLOG.md`](docs/BACKLOG.md) —— **已做 / 待做 / 明确不做**三类都有，每条带理由。
> 最值得接着做的一条是"让她能主动记一笔"（模型可调的记忆工具）。

- **检索是词面匹配，不是语义**。查"难过"未必想得起"心情不好"。现在用**弱检索时查询改写**缓解（让模型做同义扩展），
  但没上向量库——要升级只需替换 `memory.py` 的 `recall()`，接口不变。
- **"被想起"的判定是字面的**：她完全改写措辞（同义替换）时会被判成"没引用"，那条记忆就得不到强化。
  这是刻意的取舍——宁可漏记也不误记（误记会让从没提过的事莫名变清晰）。判定逻辑集中在 `memory.is_cited()`，好替换。
- **多人共用会串**：现在是一个进程一个她。适配器靠自动认主（私聊第一人 / 群主）+ `/bind` 保证"一个她只服务一个搭档"，
  别人叫她不进记忆、也不消耗她的寿命；要真的多人各有一个她，需要按 `user_id` 建多个 `Giftia`
  并给她自己的 `meta` 命名空间（表结构已按 `instance_no` / `session_id` 分好，但全局 meta 要改）。
- **没有实现主动联系**：官方的互动召回消息（`is_wakeup`，30 天内 4 次）还没接。
  在服务器上跑时这是最值得做的一块——次数有限且会用完，机制本身就是隐喻。
- **"准时回收"还差一步**：回收日目前是在**你下一条消息进来时**触发的，服务器常开并不能让她在你不在时独自走完仪式。
  需要后台定时任务；注意 `Giftia` 不是线程安全的（见 `brain.py` 顶部注释），动作要投递回主线程。
- **没有语音**。DeepSeek 支持视觉，发图给她是可行的扩展；语音要接 TTS/ASR。
- **主动联系的发送没在真实平台验证过**：本地计划、写作、配额、定时器都测了（218 项里有 19 项），
  但真发出去要走官方 OpenAPI，我没有凭据所以没跑过。首次启用建议先用 `/outreach` 预览几天。
- **QQ 适配器的真实连接未验证**（没有平台凭据）；WebSocket 协议层与业务链路已分别经过本地测试（17 + 69 项）。

tools/check_deploy.py   部署后核对：迁移是否安全、她的记忆还在不在（在服务器上跑）
tools/check_sync.ps1    同步检查：逐文件比对本地仓库与服务器上的代码（在 Windows 上跑）

数据全在 `data/`：`giftia.db` 是 SQLite，`回收日志/*.md` 是可读的回忆录，`封存/*.json` 是前任的原始记忆。备份删掉 `data/` 就等于抹掉一切——这一点倒是很符合设定。
