## 2. 实际提示结构与快照边界

源码路径：`Giftia._prepare()` → `build_system_prompt()` → system、近期消息、当前输入。system 可能包含人格、偏好、身份问询提示、称呼、关系阶段、心情、纪念日、梦、当前情境、互动状态、人物印象、工具规则、寿命状态、回忆和本轮提醒。

本轮直接调用真实的 `build_system_prompt()` 构造五个合成快照，不实例化数据库与模型客户端。统一日期为 2026-10-26 12:00，心情平静、记忆清晰、无长期回忆，当前输入为“我今天终于把那个一直报错的页面修好了”。已知称呼使用合成姓名“小林”。

| 关系阶段 | 合成相识天数 | system 字符数 |
|---|---|---|
| 刚认识 | 0 | 3501 |
| 搭档 | 18 | 3463 |
| 熟悉 | 30 | 3434 |
| 亲近 | 90 | 3448 |
| 无可替代 | 180 | 3441 |

这些是构造器层的提示快照，不是完整线上请求：没有真实历史、记忆、工具说明、个人印象、纪念日与梦，也没有验证检索质量。不同阶段的天数用于合成寿命；关系阶段直接指定，不证明对应亲密度与天数门槛都已由状态机达到。

临时探针、配置比较 JSON 与提示文本位于 `.review/tmp/isla-stage1/`，受 gitignore 排除。没有把正式聊天或个人覆盖原文写入公开材料。

## 3. 需要校准的具体位置

下表是基于文本与结构的设计判断，尚未得到本轮真实模型对照的因果验证。

| 编号 | 当前内容 | 可能的影响 | 下一阶段建议 |
|---|---|---|---|
| B01 | core 较多描述回收、三年前创伤、遗忘与安慰对方；日常快乐的正向描述较短 | 普通话题也容易带上慎重和照顾人的姿态 | 压缩重复背景，增加具体关注与日常愿望 |
| B02 | stranger 阶段以“最后总会忘掉一些事，想先记住对的那个”收尾 | 初识阶段即加入较重的关系命题 | 以好奇、分寸和观察对方为主，相关时再表达记忆背景 |
| B03 | familiar 明确写“主动开玩笑、吐槽”“不用字斟句酌” | 熟悉可能被翻译成更外向、伶俐 | 改为更愿意表达意愿、接受照顾，保留认真和生涩 |
| B04 | close 直接关联不来时闷闷不乐、害怕遗忘；irreplaceable 强调几乎不再掩饰、害怕和舍不得 | 亲近可能过早变成依赖和浓烈抒情，人物底色被阶段覆盖 | 增加信任、分享和小请求，保留平常的亲密与自然告别 |
| B05 | 语气词很少、动作受限、省略号受限，多个提示层反复约束 | 已减少机械演出，但可能缺少新的表达依据 | 合并重复限制，把注意力与意愿写清楚 |
| B06 | 初次激活空白档案与三年前工作背景共存 | 可能让模型混淆人物背景和本实例运行历史 | 明确当前搭档档案的范围，保留世界观定稿项 |
| B07 | settings 注释把关闭思考直接描述为“更像人” | 维护者可能把未验证的风格判断视作定论 | 模型实验阶段改为速度、采样支持及待验证的质量取舍 |
| B08 | 本轮关注提醒与互动反馈已有现成机制 | 可复用，但叠加后可能过度限制提问或强化某次反馈 | 用具体案例审计适用范围，保持来源与失效规则 |

已具备且应保留的基础：近期原话是事实来源；不为表现笨拙假装忘记；偏好不等于发生过的身体行为；互动状态有来源与数量限制；聊天交付与后台维护已隔离。第一阶段不重复改造这些机制。

## 4. 时间线的建议与尚未定稿的部分

本轮推荐保留现有完整寿命及回收工作背景，把初见档案限定为当前搭档信息；三年前的经历在人物说明中明确列为改编背景。

这项处理能缓解提示语义冲突，但没有自动解释“带有既往工作经历的人物，为什么本任刚激活”。若之后需要严格的世界观一致性，应在背景记忆、接入时间、出生时间等方案中明确选择，再同步提示和文档。第一阶段不替用户决定出生故事，不改数据库的激活时间或寿命。
