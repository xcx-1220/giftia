## 1. 这轮实际改了什么

### 人物与关系

修改 `config/persona.toml`：

- 把青涩、好奇、期待以及自然口语的温度放入共同底色，初识即能表达一点心情。
- 五个阶段沿着“试探着表达 → 发现可以被听见 → 更愿意说心声”发展，保留认真、生涩、自己的偏好和分寸。
- 取消熟悉阶段固定要求吐槽、亲近阶段默认因离线闷闷不乐，以及用害怕遗忘和强烈依赖定义深层关系的文案。
- 压缩重复的创伤与遗忘背景，保留终端服务、三年前经历、完整寿命及记忆退化设定，区分背景与本任实际运行时间。
- 使用自然的初见和换任问候；不以“编号已更新”“今日出厂空白档案”作为固定开场。
- 允许自然语气词和省略，按情境使用；普通分享先说一点自己的反应，减少在结尾追加问题和建议。
- 保留真实经历的来源边界，并补充讨论用户介绍的作品时不能把看法说成亲自读过。这项提示仍未完全约束住真实模型，见后文。

关系的天数、亲密度门槛、寿命、记忆算法和正式数据库均未改变。`config/settings.toml` 仅修正“关闭思考就更像人”的注释，数值与模式继续为 Off / 1.15 / 900。

### 评测与回归

新增：

- `tools/isla_character_eval.py`：通过真实 `Giftia.handle()` 流程重放合成对话，支持选人设、Off/Low、温度、重复次数、阶段、调用上限与盲评导出。
- `tools/isla_character_cases.json`：12 组主要场景、4 组阶段/分歧对照、1 组单独的工具记忆冒烟。
- `tools/isla_eval_selftest.py`：11 项离线检查，覆盖调用上限、失败记账、配置隔离、真实阶段选择、私有视角观察、推理文本不进入结果，以及工具消息回传等。

普通人物对照关闭工具、后台整理、梦、主动任务和关系/心情变化，让各组使用同一平静背景与固定阶段。每个用例创建独立临时库，不访问正式聊天。工具模式另外启用并单测。

新工具保留了原有 `tools/chat_quality_eval.py`，便于复查上一轮聊天质量实验。

## 2. 对照方法

基线是修改前的 `01dd7e9` 人物配置。最终候选使用当前本地 Persona 的全部字段，其配置指纹已与实际重放记录核对一致。

16 组主要与阶段场景每组三轮：旧人设和最终候选各独立重放两次，均为 96 条回复。温度 1.0 组重放一次，为 48 条。模型名均为 `deepseek-flash`，返回的 model 字段同名；记录了供应商返回的 `system_fingerprint`，不凭模型别名宣称永久固定在某个修订。

各版本使用相同初始合成事实、时间、关系与输入。之后接续各自上一轮回复，因此后续上下文会分支；这是连续对话比较，并非每一轮逐字相同上下文的单变量实验。

API 返回正文、usage、完成原因、耗时和错误状态保存在 `.review/tmp/isla-implementation/`，不保存推理原文。接口重试设为一次传输尝试，失败也记入预算；遇到空答或截断等异常即标记并停止该组。

耗时从 `Giftia.handle()` 调用到返回，包括本地处理与 API 等待，不包括正式网站队列、网络交付和气泡播放。组间部分并发运行，缓存和服务负载会影响耗时；这些不是正式环境的性能承诺。

含问号和省略号的数量只用于查找模式。它们表明新的好奇和生涩有时仍被模型表达成追问与停顿，不能把“更活泼”直接视为自然度达标。

Low 空正文的原始元数据：完成原因为 `stop`，生成 69 tokens，全部计为 reasoning tokens，正文长度为 0；请求上限为 4096。此次不能解释成简单的 900 tokens 不够，也不能据一次返回认定全部 Low 请求不可靠。评测没有把业务兜底台词当作正常模型回答。

中间人设版本的 Low 曾完成 48 条，但人设已修改，不能把旧版本的结果合并成最终版本的完整 Low 组。

## 4. 真实工具验证

最终候选在 Off 与 Low 下各完成一组三轮工具冒烟，各使用 4 次 API 调用：

1. 要求记住合成偏好“喜欢清淡的茶，不喜欢太甜的奶茶”。
2. 下一轮询问刚记住什么。
3. 普通告别。

两组均实际调用 `remember`。独立库观测中保留了对应的私有记忆摘要和 6 条用户/助手消息，证明不只是口头说记住；下一轮也正确回应了偏好。

这只证明本组流程可用。离线工具协议检查和少量真实冒烟不等于所有跨轮、历史裁剪、重启及模式切换都已覆盖，因此本轮没有把 Low 设为生产默认。

## 5. 人物表现的观察与剩余问题

以下是维护者阅读后的观察，未作为用户评分或完成的盲评成绩：

- 一些夸奖场景开始出现自己的高兴、难为情和想把意思说清楚的愿望，较贴近选定方向。
- 书名场景能表达想知道、愿意猜，但常连续列出几种可能，再问一个问题，仍可能显得太会解释。
- 初识与亲近的区别尚不稳定；有些初识回复已经很能分析，有些亲近回复又只是总结交流方式。
- 最终候选带问号的回复多于旧人设。温度 1.0 的一次重放没有足够证据证明能稳定解决这个问题。
- 对用户介绍的故事，仍有“我读的时候”“合上书后”等无依据的亲历措辞；来源提示已经加入，但未彻底奏效。
- 告别中仍偶见“晚上有书看”等未经建立的线下活动，以及额外作息建议。正式启用前需结合用户希望的角色生活边界进一步校准。
- 接起旧话题有时太急，用户只是回来打招呼，模型已经连续问书的结局。持续关注的相关性与分寸需要继续检查。

因此，这轮完成的是可审阅的本地人物候选和首轮实验，并未达到方案中“主观自然度、阶段成长与事实边界均验收”的发布标准。优先保持 Off / 1.15，把具体问题带入下一轮定向修正与隔离试聊。
