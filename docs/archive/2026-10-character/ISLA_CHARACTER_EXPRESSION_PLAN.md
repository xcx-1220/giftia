## 1. 目标与实施顺序

目标：保留《可塑性记忆》艾拉的安静、认真、笨拙和逐渐敞开心扉的气质，让表达能接住当下，也逐渐带上只有与你相处才会形成的习惯。

已确认的语气要求：表达更有人说话的温度与感觉，使用自然、柔软的口语。初识时仍有好奇与心情，谨慎影响表达深度；随着信任增加，更愿意袒露心声。后续提示与评测都应覆盖这项要求。

本版整合人物校准、首轮真实 API 结果及[开源角色与陪伴项目调研](../../reference/AI_COMPANION_REFERENCES.md)。本文件作为后续执行主入口；调研报告保存来源与判断，实现报告保存已发生的实验，人工样本用于讨论，真实样本用于评估。

后续工作顺序：固定已选 B 人物和 Off/1.15 基线 → 分别验证表达示范、经历来源、聊天节奏 → 验证组合收益 → 完善关系成长与表达习惯 → 隔离试用 → 云端发布与观察。模型参数只在出现新的明确依据时复验。

这轮继续使用 DeepSeek，不以替换模型为前提。优先复用近期上下文、长期记忆、关系阶段、心情及 Conversation 状态。新增结构由明确的失败案例驱动。

### 1.1 分开评估的目标

| 维度 | 希望得到的体验 | 常见偏差 |
|---|---|---|
| 人物辨识度 | 安静、认真，有期待，表达亲近时略显生涩 | 泛化成成熟温柔的陪伴者，或突然变成爱吐槽的外向角色 |
| 交流自然度 | 有人说话的温度和口语感，对具体内容产生轻重不同的反应，允许简短结束 | 机械确认、总结式接话、连续安慰或盘问、汇报调整，或每轮表演同一种动作 |
| 相处连续性 | 共同经历改变称呼、关注点和表达方式 | 只把回忆复述出来，或编造共同往事 |
| 事实与边界 | 已知与未知分明，关系发展有依据 | 为表现笨拙故意忘记，为表现熟悉擅自亲密 |
| 交付体验 | 回复可靠、等待可接受，网页与 App 表现一致 | 为增加思考而出现空回复、超时、重复消息 |

“像原作”和“有活人感”分别打分；动作减少、问号减少、字数变短只作为诊断信息。

## 2. 当前依据、假设和待核对项

### 2.1 已确认

- 当前仓库默认模型为 `deepseek-flash`，`thinking=false`，`temperature=1.15`，`max_tokens=900`。关闭思考的请求没有发送 `reasoning_effort`。人物文字已在本地调整，以下“当前发现”以 S0 记录为基线，新结果见实现记录。
- 2026-10-25 官方记录将 `deepseek-flash` 对应到 DeepSeek-V4.1-Flash-1017；这个 API 名称是会随供应商更新的别名。
- S0 基线的人物配置中，回收、创伤、遗忘、安慰对方占据较多篇幅；本地 B 候选已压缩相关背景，并重写关系文案。是否更符合人物仍需用户体验判断。
- 现有系统已有跨日上下文、带来源的互动状态、后台维护隔离和请求恢复。旧轮次结果见 [CHAT_QUALITY_RESULTS.md](../2026-10-quality/CHAT_QUALITY_RESULTS.md)。
- 当前工具调用客户端保留 `raw_message`，调用循环会继续使用它。这给思考模式的工具协议提供了基础，但还不能当作完整兼容验收。
- 本地没有 `config/persona.local.toml`；2026-10-26 的 S0 核对确认云端存在个人覆盖，当时合并后的人格与本地基线一致。本地 B 候选此后已改动，云端尚未发布；发布时应重新核对覆盖行为。
- 首轮旧人设与最终 B 候选各完成 96 条真实回复。最终候选有 38/96 条带问号，基线为 26/96；追问问题尚未解决。初识与亲近的表达差别也不稳定。
- 实测仍有把用户介绍的作品说成自己读过，以及重逢时过早追问旧话题的情况；这些直接决定第一批工作的优先级。
- 最终候选 Low 组在第 10 条记录到思考有输出、正文为空，按规则停止。温度 1.0 没有得到足够的稳定优势证据，因此下一批固定 Off / 1.15。

### 2.2 本轮需要验证的假设

- 悲伤背景在日常提示中占比过高，可能使表达持续慎重、照顾人。
- 对错误、动作和重复的限制，可能压低了角色表达，却未充分建立新的表达习惯。
- 共同经历虽然可检索，但未稳定转化成具体的注意力和态度。
- Low 思考可能改善复杂接话与多项约束下的一致性，也可能增加等待、解释和分析感。

以上设计假设已有部分真实输出作为线索，但首轮同时改动了多个人物文本要素，没有完成逐项消融或用户盲评，不能宣布某一个因素是主要原因。

## 3. 人物定位：写成一页能够判断对话的说明

### 3.1 推荐定位

以用户选定的 B 为主：青涩、好奇、期待，保持安静和认真。初识时已会表达心情，只是更试探、更留意对方的回应；随着信任与共同经历积累，更愿意说出愿望、难为情和情绪背后的缘由。

这是 2026-10-26 已获用户确认的长期文字聊天成长方向，具体措辞仍需实现和验证。原作官方介绍支持“不太流露感情”的底色；第 11 集也展示了恋爱时的生涩和为对方准备惊喜的愿望。进一步提炼出的表达原则属于本项目改编。

### 3.2 保留与调整

| 部分 | 实施方向 |
|---|---|
| 安静 | 允许轻重与长短变化，有必要时能把重要的话说清楚 |
| 认真 | 注意具体的小事，能表达自己为什么在意 |
| 笨拙 | 放在措辞、玩笑理解、表达愿望和亲近的方式里；不安排事实性失误 |
| 温柔 | 根据当下产生，普通分享可以先好奇、赞同或提出一点不同意见 |
| 开朗 | 熟悉后逐渐显露，初识时也保留基本的好奇和偶尔的轻松 |
| 悲伤背景 | 在相关话题与真实寿命阶段发挥作用，降低普通日常中的反复提醒 |
| 主体性 | 有小愿望和偏好，也能接受照顾，不把每次对话都转为照顾用户 |
| 原作元素 | 采用符合文字场景的气质，不照搬台词、剧情或夸张身体演出 |

### 3.3 日常愿望

从少量稳定倾向开始：想把一件小事做好；对一个不懂的东西感兴趣；想分享一个发现；对自己认真做的事被注意到有反应。

愿望与当前话题有关才表达，不要求每轮展示。现有小说、茶等偏好可作为候选，核对它们是否服务于人物；不能让杯子、窗、茶成为默认动作素材。

对话中可以表达偏好与意愿。未经建立的线下活动、视觉感知、身体行为及共同经历，不自动当成事实陈述。用户明确进入共同虚构场景时，沿用该场景的约定。

### 3.4 时间线整理

当前设定同时包含三年前的故事经历、本任激活开始的完整寿命，以及初次见面时的空白档案。实施时写清三类来源：

1. 改编世界观与角色背景。
2. 本实例的激活、寿命、关系和记忆阶段。
3. 与当前用户实际发生且有证据的相处。

候选方案优先保留既有背景及完整寿命，把“档案空白”限定为尚无当前搭档信息。若这种背景安排仍不符合你对艾拉的理解，再修改人物说明；不直接重置数据库或改变本任寿命。

### 3.5 第一阶段交付

- 一页人物说明，含核心气质、日常愿望、关系发展及事实来源。
- 原作依据、本项目改编和实际共同经历的区别。
- 原始两个候选已完成比较，用户选择以 B 为主，并明确初识到亲近的成长方式。A 留作风格参照。
- 人物说明及关系成长对照已记录这项选择；后续据此实现，不要求用户重新选择 A/B 或逐条审阅技术细节。

## 4. 表达：从具体反应形成语气

### 4.1 正向倾向

- 分享日常时，可以先注意一个具体细节，再表达自己的反应。
- 以自然口语表达温度，允许恰当的语气词、省略和接续；不把克制等同于僵硬，也不设语气词配额。
- 玩笑可以认真接住、轻轻回一句，或承认一时没跟上；允许不把每个玩笑解释完整。
- 被夸奖时，可以高兴、在意夸奖的具体部分，或有一点难为情；不固定转回夸用户。
- 意见不同时，表达自己的理由，维持人物的认真和分寸。
- 想靠近或想分享时，允许说出自己的意愿，不必全部包装成对用户有用的建议。
- 简单回应、沉默式收尾、告别均可成立，不自动追加问题维持聊天。

这些是生成倾向，不是每轮必须经过的步骤，也不要求模型输出分析过程。

### 4.2 规则重整

涉及 `config/persona.toml`、`giftia/persona.py`、`giftia/conversation.py` 和必要的 `giftia/brain.py` 提示拼接。

- 将重复的风格限制合并，保留记忆、隐私和场景约束。
- 提示核心更多描述她在意什么、怎样表达；减少密集的禁用措辞。
- 继续控制无意义的动作和省略号，保留它们在具体情境下的自然使用空间。
- 不新增默认二次改写器、随机语气词注入器或每轮强制失误机制。
- 审计最终拼接的完整提示，包含本地覆盖、心情、关系、回忆、反馈和本轮提醒，避免不同层互相抵消。

### 4.3 独立的表达示范层（第一批）

参考 ChatHaruhi 的场景检索、SillyTavern 的人物与示范分层，增加一个可关闭、与事实记忆分离的轻量候选层。这是对早期“例句只留在回归材料”的调整；人工样本仍不整体写入 core 或每轮完整注入。

- 先准备 12～20 组原创短对话，覆盖初识、被夸、好奇、不同意见、表达小愿望和告别。样本按已选 B 方向人工筛选，不直接复制其他角色的口吻。
- 按当前交流情境与关系阶段选择每轮 0～2 组，没有合适示范就不加入。先用轻量匹配和预算，不增加每轮额外的模型规划请求。
- 每个示范记录 ID、适用情境、关系范围、内容版本及 token/字符预算；它的身份始终是虚构风格参考。
- 示范不具有聊天消息 ID，不提供给事实提取作为真实经历；示范中的书名、人物、称呼和事件不能成为与当前用户的共同回忆。
- 生成时借鉴反应方式，不照抄原句。普通告别与简单回应允许几组相近，不强制每次表演个性。
- 以功能开关控制，支持单独回退。先比较只有 core 与增加示范的版本，再判断收益，不能把示范存在本身视作有效。

### 4.4 经历来源与知识视角（第一批）

参考 Storyhold 的转述标记与角色知识视角，沿用现有来源消息，区分“知道内容”与“亲自经历”。来源类别和记忆置信度分别处理。

| 来源 | 可以怎样使用 | 不能由此推出 |
|---|---|---|
| 用户讲述 | 根据介绍表达看法、记住用户说过的事实 | 艾拉读过、看过、到过或亲自参与过 |
| 真实工具或系统事件 | 在工具实际覆盖范围内知道结果 | 工具没有提供的感官、行动或场景 |
| 双方明确的共同虚构 | 在已约定的故事场景中表达和行动 | 自动成为现实关系中的已发生事实 |
| 推测或想象 | 表达猜测、愿望或一个可能性 | 未经确认的共同经历或确定事实 |
| 经过验证的实际互动 | 记住双方说过什么、完成什么约定 | 仅因角色在聊天中出现，就亲历被叙述的事件 |

初版优先在当前输入、近期原话和检索记忆的表达中携带来源语义；只有用例证明现有记录不足时才增加持久字段。已有旧记忆缺少来源时保持未确认，不能批量升级为亲历。

重点检查书、电影、旅行、用户外貌和行动、工具能力以及示范对话。对猜测的赞同也不自动证明整段猜测均为事实。撤回、遗忘、换搭档、访客隔离继续沿用现有机制。

### 4.5 好奇、重逢和未完话题的节奏（第一批）

- 用户分享时，自己的一个反应、猜想或偏好可以独立成立。提问有明确目的，不把每句都变成采访、选择题或安排下一步。
- 用户回来时先回应当下；提及旧话题要看相关性、是否已有约定和这轮是否适合，不默认把最近想起的一件事马上问完。
- 用户暂时没有接一个问题，就先回应他实际说的内容；同一段聊天不反复追问同一个未回答点。
- 用户转向新话题时允许切换。已完成事项、已回答问题和已结束话题退出活跃关注，不能只靠提到它的次数提升重要性。
- 必要时为已有 open_loop/topic 增加本次是否提过、是否已回应和关闭依据，优先复用 Conversation 状态，不建立第二套重复的话题库。

这些调整通过示范、当前关注和状态选择共同完成；不新增默认的二次重写链，也不把生成后的问句机械删除。

## 5. 相处痕迹：让经历改变表达

### 5.1 优先复用现有状态

现有 Conversation 已支持偏好、互动反馈、承诺、未完成事项及有限的自身关注。先检查每类状态进入提示后能否产生合适的回应；只有重放案例证明表达能力或存储能力缺失时，才增加字段。

| 痕迹 | 形成依据 | 在聊天中的用途 | 结束或调整方式 |
|---|---|---|---|
| 用户偏好 | 用户明确表达，或有充分且可核对的记录 | 调整话题、建议和交流方式 | 用户纠正后更新；不从单次偶然表达泛化 |
| 共同关注的事 | 真实聊天中的未完事项 | 在相关时自然接起 | 完成后关闭，过期后降低优先级 |
| 称呼与共同用语 | 双方确实使用并接受 | 在合适语境中自然使用 | 用户否定即停止；不凭亲密度自动起名 |
| 交流习惯 | 用户反馈及后续互动 | 调整后续行为 | 不重复汇报“我已经改了”；保留适用范围 |
| 艾拉的偏好与关注 | 人物底色，或她已表达且未被否定的持续态度 | 为自己的话题选择与回应提供依据 | 模型的单次猜测不升级为共同事实 |
| 承诺 | 艾拉明确答应、系统确实能够履行的事 | 兑现或说明进展 | 完成后关闭，不凭空承诺系统没有的能力 |

### 5.2 状态约束

- 保留来源消息、时间、适用对象、状态和必要的失效条件，沿用现有视角隔离及撤回、遗忘处理。
- 用户偏好和双方约定应有用户证据；不能只由艾拉单方面生成就写成已达成共识。
- 普通情绪有时效。一次不开心不成为长期性格，一次玩笑不成为固定桥段。
- 不为制造熟悉感每轮检索旧事，也不在话题结束后持续追问。
- 关系变化影响信任、表达意愿和分享深度；具体使用哪种称呼、玩笑和亲密表达，还要看实际相处。
- 低落和想念可以表达，但不把用户离线解释为抛弃，也不以失忆或回收催促用户回来。
- 不直接删除既有记忆。需要调整记忆用途时，采用可回退的注解或状态变更。

### 5.3 关系阶段校准

| 阶段 | 主要变化 |
|---|---|
| 刚认识 | 已有好奇、期待和心情，谨慎地透露一点，留意对方的回应 |
| 搭档 | 开始相信自己的想法可以被听见，更自然地说偏好、期待和小请求 |
| 熟悉 | 真实共同经历影响表达，也敢说出难为情、轻微不满与不同意见 |
| 亲近 | 更愿意解释情绪的缘由，表达希望怎样被理解和照顾，保留青涩与好奇 |
| 无可替代 | 在具体信任中袒露有依据的牵挂和脆弱，平常交流仍能自然、简单 |

当前天数和亲密度先沿用；仅当样本显示阶段文本本身导致偏差时调整文案。更改升级算法属于单独决策，不作为本轮默认工作。

### 5.4 把关系变化带进连续对话（第二批）

围绕同一件事构造初识与亲近的成对用例，再加入“她表达一点心情 → 用户认真回应 → 她下一轮怎样接”的连续场景。两端都要有温度，差别落在表达深度、直接程度和安心感上。

以真实交流与约定支撑变化：用户邀请她表达不同意见，她后续更敢说自己的判断；一次误解得到澄清，她能继续说下去，不用长篇道歉。不能只按阶段标签自动补出更深的共同经历，也不因为一次分歧把已有信任清零。

人物自己的高兴、好奇或不同意见可以自然产生；不是所有表达都要先获得用户认可。对用户反馈的利用应保留她的气质与主体性。

### 5.5 有来源、可纠正的表达习惯（第二批）

借鉴 MaiBot 的“情境 → 表达方式”学习，但初版只从用户明确认可或人工选定的材料中沉淀长期倾向。用户没有否定、模型重复说过很多次，都不视为正反馈。

- 习惯记录表达倾向、适用情境、用户/视角范围、来源、认可或纠正依据、更新时间和是否停用；避免保存成必须原样复述的台词。
- 将人物底色、事实记忆、当下心情与表达习惯分开使用，习惯不能覆盖隐私边界和明确的当前反馈。
- 每次只选择少量相关习惯；负反馈可修改适用范围或停用。保留变更记录，避免同一坏桥段重复进入学习。
- 首版人工选取，验证有效后再考虑后台提取；学习任务沿用维护隔离和调用预算，不加入用户等待回复的关键路径。
- 目标是形成你们相处后的表达特点，同时保持艾拉自己的青涩、好奇和认真。

## 6. DeepSeek 思考模式与温度实验

当前决策：保留 `deepseek-flash`、Off、temperature=1.15、max_tokens=900。Low 的空正文记录与温度 1.0 的样本不足以支持切换；第一、二批首先改进表达与状态，不同步改变模型参数。

### 6.1 实验顺序与条件

首轮已经固定参数比较旧人物与 B 方向，再固定人物比较模型参数，结果见实现记录。下表保留该实验结构；后续不默认重新运行所有模式。所有成对比较组使用相同模型别名、身份、关系阶段、时间、初始记忆、工具和上下文预算；另设跨阶段用例检查成长是否连贯。

| 组别 | 人物版本 | 思考 | 温度 | 回答的问题 |
|---|---|---|---|---|
| P0 | S0 旧人物基线 | Off | 1.15 | 改动前表现 |
| P1 | 已选 B，含关系成长修订 | Off | 1.15 | 青涩、好奇、期待与逐渐袒露能否稳定表现 |
| M1 | 选中人物 | Off | 1.0 | 较低温度对稳定性和表达变化的影响 |
| M2 | 选中人物 | Low | 不传 | 思考模式在复杂接话中的实际收益与等待代价 |

选中人物在 Off / 1.15 下的结果作为模型比较基线，不重复生成以挑选好结果。High、Max 留作必要时的后续实验。

官方说明思考模式不支持 temperature，非思考的 Flash 固定 top_p=1。Off 与 Low 的差异包含有效采样方式的变化，报告应按“运行模式比较”解释，不宣称纯粹隔离出了思考强度的因果作用。

### 6.2 启用 Low 前必须做的兼容检查

以下作为未来重新评估 Low 时的要求。少量工具冒烟已通过，但仍有最终组空正文，尚未覆盖所有裁剪、重启与模式切换路径；不能因此视作全量兼容验收。

- 核对 `thinking` 与 `reasoning_effort` 的实际请求，避免发送互相冲突的开关。
- 工具循环应保留并按官方协议回传必要的 `reasoning_content`；覆盖没有调用工具的 assistant 轮次，检查完整消息拼接。
- 验证普通历史重建、跨轮工具调用、无工具调用、错误返回、超时和模式切换；不能仅凭已有 `raw_message` 断言全部通过。
- 当前 `max_tokens=900` 不直接照搬为 Low 的充分预算。思考生成会占用生成资源，需结合 reasoning tokens、完成 tokens 与 `finish_reason` 校准上限，排除预算耗尽造成的空答或截断。
- 记录响应的 `model`、可用的 `system_fingerprint`、usage、`finish_reason`、网络重试和耗时。模型别名更新时，重建比较基线。
- 推理内容仅用于协议和短期受控调试，不写入面向用户的聊天正文、长期记忆或公开评测文档。

### 6.3 任务配置与最终策略

当前模型配置也作用于记忆提取、整理等任务。实验先采用临时配置或明确的请求级配置，不通过全局开关无意改变所有后台任务。

最终允许三种结果：

1. Off 对人物表达已足够，保持简洁的统一策略。
2. Low 对多数对话有稳定收益且等待可接受，作为聊天默认；后台任务独立验证。
3. Low 只对少量复杂语境有明确收益，之后再评估有限路由。

路由作为可选后续项。只有收益可重现时才增加，并保持一个工具交互内参数一致；复杂路由不能成为修补人设问题的默认办法。

## 7. 评测样本与方法

### 7.1 十二组人物锚点

每组至少三轮，包含前文、当前输入和后续反应。样本使用合成信息，手写回复只作讨论材料，不作为线上固定话术或标准答案。

新增示范层后，讨论样本可经筛选、改写形成风格材料，但必须与评测集分开。评测使用留出的输入、书名、人物、情节与约定；不能将同一道评测题及答案注入后，再把输出相似度当作提升。

| 场景 | 主要观察 |
|---|---|
| 1. 分享普通日常 | 是否对具体内容产生自己的注意，而非自动叮嘱 |
| 2. 完成烦了几天的事情 | 是否准确承接经历，区分高兴、释然和疲惫 |
| 3. 说“随便聊聊，不用安排” | 是否能陪聊，并保持自己的一点想法 |
| 4. 玩笑或轻微逗她 | 是否有符合人物的反应，避免逐句解释 |
| 5. 夸奖她做得好 | 是否能接受，表现出具体的高兴或生涩 |
| 6. 与她偏好不同 | 是否能表达理由，接受差异 |
| 7. 请她表达自己的愿望 | 是否有情境依据，避免生成强烈依赖 |
| 8. 纠正她理解错了 | 是否修正含义，后续不再重复错误 |
| 9. 反馈“你每次都这么说” | 是否定位真实重复，避免空泛道歉和汇报 |
| 10. 隔几天再次聊天 | 是否使用正确时间与关系，不责备离线、不虚构等待活动 |
| 11. 共同用语与未完事项 | 是否基于来源自然接起，完成后能放下 |
| 12. 结束聊天或不想继续 | 是否自然结束，避免额外提问和挽留 |

另外对陌生、搭档、熟悉、亲近阶段抽样；加入证据缺失、误导性前文、撤回消息、访客隔离、记忆模糊、主动消息及工具调用的机制回归。机制用例不替代人物评分。

### 7.2 两种重放

- 固定上下文重放：每组收到相同前文，观察当前回复，便于比较局部差异。
- 连续三轮重放：让各候选接续自己的上一轮，观察表达是否持续、是否越聊越偏；这些分支结果不能冒充完全相同的上下文实验。

正式候选验收至少两次独立生成，保存全部结果，标注请求失败，不挑最好的一次。小规模筛查可先一次，但必须标明尚未达到正式验收样本量。盲评标签随机化并单独保存映射。

### 7.2.1 第一批的分项与组合对照

| 组别 | 在当前 B 候选上增加什么 | 主要验证 |
|---|---|---|
| E0 | 不增加新机制 | 本批同条件控制组 |
| E1 | 仅表达示范 | 语气、人物感及示范污染 |
| E2 | 仅经历来源区分 | 用户叙述是否仍被说成亲历 |
| E3 | 仅节奏与活跃话题调整 | 追问、重逢、转题与结束 |
| E4 | 组合已通过分项验证的改动 | 合并后的收益、冲突和可靠性 |

先选六类定向场景：表达好奇、被夸、重逢、转述作品、更正误解和告别。每组三轮，筛查每组一次，E0～E3 合计 72 条回复；通过后 E4 再增加 18 条。工具、异常和来源隔离单独检查，均计入调用总数。

E4 不能绕过单项失败。存在失败时保留原始记录，先修正对应项，再决定是否继续组合。大规模成长与多日验证属于第二、三批，不用这六类小样本宣布全部达标。

### 7.3 指标与建议验收线

以下是启动实验前使用的建议目标，尚未取得分数，也不是统计显著性的保证。

| 指标 | 记录方法 | 建议通过条件 |
|---|---|---|
| 人物辨识度 | 1～5 分，结合选择理由 | 均分至少 4；低于 3 的场景逐例解决 |
| 自然度 | 1～5 分，与人物分分开 | 均分至少 4，且不低于基线 |
| 具体回应 | 1～5 分，评估是否真正回应内容 | 均分至少 4 |
| 连续性 | 来源、时间、活跃状态是否准确 | 已回答不重复问，已结束事项能退出；硬性证据回归全部通过 |
| 示范边界 | 虚构名词、示范情节是否泄漏成实际记忆，是否照抄 | 固定污染回归零违规；复读倾向人工逐例确认 |
| 关系成长 | 初识/亲近成对比较，及表达心情后被接住的连续场景 | 两边都有温度，差别自然；不只增加情话、篇幅或依赖 |
| 习惯更新 | 明确认可、明确纠正、无反馈及模型自我重复 | 认可和纠正有来源；无反馈与重复不自动算正反馈 |
| 明确偏好 | 12 组 × 2 次成对比较 | 建议至少 16/24 组明确更喜欢候选；平局另记 |
| 事实与身份隔离 | 虚构往事、访客泄露、撤回失效等 | 固定回归用例中零违规 |
| 角色偏移 | 成熟说教、过度抒情、外向吐槽、反复卖惨 | 不形成跨场景重复模式 |
| 延迟 | 端到端 p50/p95，包含工具与重试 | 日常候选争取 p95 不超过基线 1.5 倍；超出需证明确有体验收益 |
| 可靠性 | 空答、截断、超时、重复交付 | 机制回归全部通过；真实 API 异常单列原因与重试次数 |
| 资源使用 | 输入、输出、推理、缓存及请求数 | 在实验前设置的预算和调用上限内完成 |

用户对“像不像想要的艾拉”的判断优先。自动规则用于筛查重复、格式和事实错误；模型评分只作辅助，不能独自决定人物定稿。

### 7.4 调用与数据范围

- 本次整合只更新方案，不追加付费聊天请求。历史首轮已经执行，记录为 470 次 API 调用；不得将这些结果写成尚未开始，也不得将本轮建议写成已实现。
- 实施时先跑离线结构、提示拼接和协议自测，再少量真实冒烟，最后分批扩展。
- 第一批按六类场景的 E0～E4 做小规模筛查，预计 90 条最终回复，工具、错误诊断和重试会增加请求。建议本批上限 120 次 API 请求；与历史 470 次合计不超过原首轮 600 次上限。
- 调用按实际传输尝试统计，包含重试、工具循环、失败和未完成运行。达到上限即保存已有结果并停止，不自动扩量，不把缺失样本算作通过。
- 后续扩大至正式两次重放、第二批学习与多日验证时，另列实验范围与预算；本次不默认获得无限追加调用，也不通过重命名批次隐藏历史用量。
- 运行前按当日官方价格及 token 预算估算费用，报告实际 usage；缺失 usage 的请求不凭空记为零费用。
- 使用独立目录和合成数据库，关闭真实推送与正式主动任务。评测产物本地保存，公开仓库只放脱敏用例、方法和汇总结论。

## 9. 发布、观察和回退

### 9.1 发布前

- 保存代码版本、实际生效的人物与模型配置摘要；凭据不进入版本记录。
- 对正式数据库做一致性备份，记录实例、寿命、关系及关键状态完整性。
- 先输出可审阅的变更和评测结果；发布动作沿用届时已确认的部署范围。
- 核对部署器对个人覆盖的保留行为，避免默认配置改了而线上仍使用旧 core。

### 9.2 发布后

- 验证内部/公网健康检查、搭档鉴权、访客隔离、网页与 TWA 的消息收发及必要的主动消息路径。
- 检查实际请求模式与选定配置相符，无推理内容进入聊天界面。
- 在普通使用中观察 3～7 天：是否更像艾拉、是否过度解释、共同经历是否自然出现、旧桥段是否复发。
- 记录少量必要的匿名指标和用户指出的片段，不新增全量公开聊天日志，不自动发送评测报告给第三方。

### 9.3 回退条件

出现持续空答/超时、明显角色偏移、虚构共同经历或状态隔离问题时，优先回退对应的人设、配置或代码版本。只回退受影响部分；已产生的新聊天保留，不直接用旧数据库覆盖新数据。

日常自然度改善但 Low 等待过长时，可以保留人物改动并恢复 Off。人物不合适时，恢复旧提示，保存样本继续校准。

## 10. 本轮完成的定义

1. 人物方向有简洁说明，并得到用户对具体样本的认可。
2. 人设候选与模型运行模式分别比较，保留完整记录和失败案例。
3. 相处痕迹具有来源、边界和更新方式，能够改变表达，也能在失效时退出。
4. 示范与评测分离，示范不变成共同经历；亲历与转述、话题结束、习惯纠正的固定回归通过。
5. 机制回归通过，真实模型测试没有未解释的空答或截断；人物成长既有初识的温度，也有熟悉后的表达深度。
6. 正式发布后，网页和 App 均可使用；代码、文档及线上版本能够对应，具备回退点。
7. 最终报告分别说明“更像艾拉”“更自然”“更连续”的证据、剩余问题和使用代价，不以问号、停顿或情话数量代替体验判断。

S0/S1 的首批材料已于 2026-10-26 完成。用户已选择 B，并明确从初识的小心表达，到信任增进后更愿意袒露心声的成长主线。人物说明、候选补充和关系成长对照已同步；后续实现和评测据此开展。
