# 网页、身份与推送

依据：2026-11-04 仓库阅读。当前入口为网页 [giftia.icu](https://giftia.icu) 和同站点安卓 TWA。部署与备份只在[运行维护](OPERATIONS.md)维护，未来工作只在[路线图](ROADMAP.md)维护。

## 进程与请求

`webgate.py` 的 HTTP 线程认证、限流、入队、等待，不直接操作 SQLite 或 `Giftia`。主线程每次最多排空 2 个请求；网页模式循环间隔 0.05 秒，主回复仍串行。队列容量为 5；后台维护的网络/计算分离不等于主模型并行或流式。

客户端用 `request_id` 标识一次发送。相同身份、同编号、同内容复用已有任务；同编号不同内容返回 409。前端等待 45 秒后可查询结果，服务端等待窗口为 60 秒；超时不意味着生成已取消，不应盲目以新编号重发。

请求账本默认保留 24 小时、最多 256 条。已落库回复可在重启后恢复；生成中断而无可恢复回复时明确失败，不保证自动重跑整轮。结果读取按搭档 epoch 或访客身份隔离。

## 身份与现有边界

| 登录方式 | 角色和行为 |
|---|---|
| `AILA_WEB_SECRET` | 搭档 owner，与核心搭档视角相连，可订阅/读取主动通知 |
| `AILA_WEB_FRIEND_PASS` | 访客 friend，通过 `aila_visitor` 区分个人记忆；不推进搭档关系、不能读取搭档推送 |

认证 cookie 采用 HMAC，带 HttpOnly、SameSite=Strict 和长期有效期。访客 ID cookie 目前未签名，清 cookie/换环境会产生新身份；持有公共访客口令不等于拥有独立账号。前端 localStorage 保存用于自动登录的口令，“忘记口令”的界面操作不等同于服务端认证 cookie 撤销。不要将这些边界写成完整账号系统，核实与改进归入 W2。

网页聊天直接进入 `handle_message()`，没有 CLI/QQ 斜杠命令分发。历史列表按 `view_id` 隔离，访客只看自己的服务端记忆分区。

## API

| 方法 | 路径 | 行为 / 权限 |
|---|---|---|
| POST | `/api/login` | `{pass}`，成功发认证 cookie；错误口令 401 |
| POST | `/api/chat` | `{text,request_id?}`，已登录；完成 200、等待 202，同编号冲突 409、限流 429、繁忙 503、执行失败 502 |
| GET | `/api/chat/result?request_id=...` | 查询本人请求，完成 200、等待 202、没有 404、失败 502 |
| GET | `/api/session` | 当前身份、`view_id`、`known` 和问候；未登录 401 |
| GET | `/api/health` | HTTP 入口存活，公开；不检测模型/队列/推送 |
| GET | `/api/push/status` | 搭档专用，返回是否有订阅、总数和 VAPID 公钥 |
| POST | `/api/push/subscribe` | 搭档专用，保存浏览器订阅 |
| GET | `/api/push/last` | 搭档专用，最近主动消息或空对象 |
| POST | `/api/push/test` | 搭档专用，实际发送测试通知；HTTP 200 仍须检查 `sent/total/error` |

无权限的推送请求返回 403；消息空文本/无效编号等返回 400。接口细节以 [`webgate.py`](../giftia/webgate.py) 为准。

## 前端与缓存

原生 `web/app.js` 保存最近 100 条显示历史和未完成请求，等待中可编辑草稿，响应按分段显示。大于约 5 分钟的间隔与跨日显示时间分隔；日期来自设备时间。界面认识天数目前按本机首次打开计算，不能当服务端关系天数。

显示文本使用文本节点，不渲染任意 HTML。service worker 缓存静态壳，绕过 `/api/`；离线只能打开已有壳和本地历史，无法离线生成。网站更新可能要刷新或重新打开才看到新静态资源。

服务端拥有相同角色记忆不代表设备共享完整聊天列表。目前没有服务端全量历史拉取，推送补入仅最近一条主动消息；跨设备改进见 W3。

## 主动通知链路

主线程每 600 秒检查一次主动联系。网页模式仅面向搭档，无订阅时不生成；默认每天 3 条、30 天 60 条、最小间隔 3 小时，安静时段为 23:30～08:00（终端服务迫近的特殊规则以代码为准）。

`push.py` 用 VAPID 发送空载荷唤醒；service worker 再携搭档 cookie 读取 `/api/push/last`。腾讯云到部分浏览器推送服务的直连曾不可用，项目用 Cloudflare Worker 中转，并限制目标主机、校验中转密钥。

至少一家推送服务接受后才写入主动历史/额度；全部失败则恢复上一条通知文本。供应商接受、SW 取正文、设备实际显示是不同阶段。最近一条消息机制可能遗漏中间消息，目前没有可靠设备显示回执。

当前订阅按钮按全局是否存在订阅显示，第二台设备可能被隐藏；W1 负责逐设备订阅与补取验收。测试通知会真的发送，设备验收只在明确的验收任务中执行。

## 接入配置与设备验收

| 环境键 | 用途 |
|---|---|
| `DEEPSEEK_API_KEY` | 真实模型 |
| `AILA_WEB_SECRET`、`AILA_WEB_FRIEND_PASS` | 搭档 / 访客口令 |
| `VAPID_PRIVATE_KEY` | 服务端签名并推导公钥；不是浏览器可公开值 |
| `VAPID_PUBLIC_KEY` | 生成工具给出的公钥；当前服务端以私钥推导结果为准 |
| `VAPID_SUBJECT` | VAPID 联系标识 |
| `PUSH_RELAY_URL`、`PUSH_RELAY_SECRET` | 中转地址（含 `/push`）与 Worker `RELAY_SECRET` 对应值 |
| `QQ_BOT_APPID`、`QQ_BOT_SECRET` | 恢复 QQ 时才需要，网页运行本身不需要 |

全新安装且尚无 VAPID 密钥时，可在受控终端执行 `python -m giftia.push --gen`。工具把私钥和公钥输出到终端，不自动写入 `.env`；通过运维凭据流程保存，不将输出贴进文档或日志。已有服务沿用原密钥，日常不要重新生成替换。

首装事故与历史配置背景保留在[旧网页记录](archive/2026-10-project/WEB_LEGACY.md)。当前运行维护按本页及运维指南执行，不能用文档占位值覆盖服务器。

设备验收依次核对 HTTPS 与 SW、搭档登录、通知权限、本机订阅、服务端记录、中转接受以及实际通知显示；关闭/重开和第二台设备单列。检查只读状态成功不能代替发送测试；浏览器成功也不能代替 Android TWA 实机结论。
