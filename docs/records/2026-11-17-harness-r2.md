2026-11-17（Asia/Shanghai）。R1 已由用户确认通过。从 Harness `0.2.2-rc.3`、艾拉 bundle `0.2.0` 和示例 bundle `0.1.0` 接续。本轮变更在本地隔离环境验收，沿用云端和 R1 已部署的冻结候选。 [R1 与真实模型记录](2026-11-17-harness-stage5-live.md) · [实施计划](../HARNESS_PLAN.md)

## 附件撤销与日志恢复

- 删除 PDF 时先把授权会话标识和附件 ID 写入独立的 `web-revocations.db`，随后清理网页任务、页文本和关联问答。查询与入队检查均使用撤销账本。附件自然到期按快照里的绝对有效期处理，关联问答同步失效。
- 附件库恢复须带当前撤销账本，恢复命令拒绝从待恢复的历史快照取账本。已启用撤销账本的网页数据库在账本缺失时拒绝初始化。切换写入方前应停止相关写入，并交接最新账本。旧快照中的字节仍按各自的备份保留周期处置。
- PDF 问答使用关闭会话持久化的独立 Harness 进程，单轮结束后关闭该进程。授权追问继续从网页数据库读取同一附件的历史。验收回执保留计时数字，普通聊天仍沿用原生会话文件。
- 快照和恢复会排除带 PDF 数据标记的旧 `session.v4.jsonl` 所在会话目录。对原始旧备份和既有云端日志的清理仍属于 R2 保留策略，需按实际目录及保留期限执行。

## 正式模式与 HTTPS 认证

新增 `serve_release.py`。正式模式读取指定的现有 Giftia 数据库及设置、人物配置和同目录个人覆盖，启动前核对数据库当前绑定的搭档，使用现有 DeepSeek 配置和服务端注入的模型凭据。DeepSeek 基础地址接上 Harness 的 `/anthropic` 路径。拒绝用合成库启动正式模式。`--rehearse` 使用同一 HTTPS 认证路径，要求合成数据库并使用模拟模型。

发布配置 `--manifest` 指定 `origin`、`owner`、`accounts`、`settings_file` 和 `persona_file`。`origin` 是一个完整 HTTPS 来源，两个配置文件使用绝对路径。`accounts` 以 Giftia 主体为键，每个主体使用独立的随机 32 字节登录凭据，配置只存 `token_urlsafe(32)` 所生成字符串的 SHA-256 十六进制摘要。通过受控渠道发放凭据。搭档取数据库当前绑定主体，访客须独立确认历史归属后才配置相应主体。若无法确认，使用新的访客主体。旧站共享访客口令、`aila_visitor` 与隔离 Bearer 不用于正式认证。

网关仍绑定回环。HTTPS 代理需保留匹配 `origin` 的 Host、覆盖 `X-Forwarded-Proto` 为 `https` 并限制源站只在回环访问。写请求须携带精确匹配的 Origin。会话 Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Strict`，有效期为 7 天；`web-sessions.db` 保存会话摘要，可跨服务重启恢复，退出时服务端撤销。轮换某账户的凭据摘要并重启后，该账户原会话失效。

```text
python harness/serve_release.py --root PREPARED_STATE --database EXISTING_GIFTIA_DB --manifest PROTECTED_MANIFEST
```
