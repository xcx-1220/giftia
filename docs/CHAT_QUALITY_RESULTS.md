## 已实现

| 部分 | 具体行为 |
|---|---|
| 人格 | 移除每轮初见、静态激活年龄、只有回忆块才算已知等冲突；减少动作/停顿指令；提供两项可修改的小偏好，不能把偏好当作当天经历 |
| 接话 | 根据当轮告别、纠正、少问/少动作反馈提供简短指引；明确少问反馈立即按原话记录，近期违反时最多重生成一次，不裁掉原句 |
| 情绪 | 完成类“吃完了/做完了”等不再误判为负面；识别“高兴不起来”、喜欢的游戏停服等组合；心情作为背景，不覆盖用户语义 |
| 记忆 | 附加分类与来源证据表；互动反馈、未完事项与助手台词分开；抑制反复道别表演；同主题偏好可更新；旧正文与原始聊天保留 |
| 连续性 | 默认最近 36 小时原话跨日读取，同时限制条数/字符；按完整 subject_id、实例与换任水位线隔离；提供原话回查 |
| 状态 | 有来源的少量话题、未完事项、互动偏好、自身关注；限量/过期/完成/撤回处理，非核心状态服从退化阶段 |
| 维护 | 持久任务、限量队列、失败重试、重启恢复；工作线程只做网络/纯计算；结果由主线程验证与提交，撤回/遗忘/换任后的旧结果作废 |
| 网页请求 | 严格有界队列；request_id 去重；结果查询与身份隔离；重启后恢复已落库回复，避免重复生成；执行中断且无回复时明确失败，不盲目重发 |
| 网页体验 | 等待时可编辑草稿；减少固定分段等待；服务器提供与身份一致的问候；本地历史和待处理请求按视角隔离，搭档旧历史可迁移 |
| 主动联系 | 加入近期交流与持续关注，抑制相似内容，近期交流后留出间隔；无订阅不生成；推送服务全部拒绝时不写入主动历史/额度，恢复上一条通知文本 |
| 发布 | 模型配置一致性检查、代码/数据库备份、可预览的记忆策略修复、明确完成词误判的状态校正，以及失败自动回滚；回滚不替换实时数据库 |

没有增加第三方运行依赖，没有更改亲密度或当前实例寿命。

## 同模型多轮对照

建立了 24 组、每组 4 轮的合成情境。24 组均完成 Mock 流程核验；真实模型选其中 12 组做对照，每版 48 条主回复。评测使用独立临时数据库，不写正式聊天或发送推送。

模型为 deepseek-flash，temperature=1.15，thinking=false。对照固定初始关系为约 18 天、亲密度 34.85；这些是合成条件，不能替代真实用户体验。

| 指标 | 旧版 | 最终候选 |
|---|---:|---:|
| 主回复 | 48 | 48 |
| 含括号动作 | 29 | 0 |
| 含省略号 | 33 | 6 |
| 含问号 | 11 | 21 |
| 评测 API 请求数（含工具/整理） | 62 | 62 |

中间发现并修复了时间标签被抄入回复、对反馈辩解、以及只口头答应少问的问题。包含旧版、三个中间候选和最终候选的全部迭代共 240 条主回复、312 次模型请求。没有调用其他模型。

**这些数据支持“动作与标点表演明显减少”，不能直接支持“活人感已经达标”。** 新版整体疑问句更多，个别输出仍有过度推断、空泛安慰或评判式措辞。例如对升职压力的回应中出现过不合适的岗位归属猜测；这不能当成理想回复展示。

明确少问后的相邻几轮在最终样本中没有再出现疑问句，但邀请对方继续说与真正产生自身反应之间，仍需审阅。自动校验只识别形式明显的问题，不是语义质量裁判。

逐场景盲评材料生成在本地 `.review/tmp/quality-blind-review.md`，随机映射另存。原方案“至少 8/12 组偏好新版”的用户盲评尚未完成；用户随后明确要求先部署到云端体验，已发布可回滚版本，不把部署成功当作自然度验收通过。

同步评测耗时包含当轮整理/工具等过程，不可当作新网页维护解耦后的端到端延迟。正式 P50/P95 需上线后按新增指标观察。

## 使用与回退

默认行为配置：

```toml
[memory]
context_hours = 36
background_maintenance = true
conversation_state_enabled = true
```

`context_hours=0` 恢复只读当日上下文；`background_maintenance=false` 恢复同步整理；`conversation_state_enabled=false` 停用新对话状态注入与更新。人格回退使用发布前的 persona.toml 快照；记忆策略调整用独立撤销命令。

隔离评测默认 Mock，只有 `--live` 才使用 API：

```powershell
python tools/quality_selftest.py
node tools/web_quality_selftest.js
python tools/chat_quality_eval.py --limit 24 --output .review/tmp/quality-mock.json
python tools/chat_quality_eval.py --live --limit 12 --max-calls 120 --output .review/tmp/quality-live.json
```

历史记忆先预览，应用与撤销都不删除原文：

```bash
python3 tools/quality_repair.py --db /opt/giftia/data/giftia.db
python3 tools/quality_repair.py --db /opt/giftia/data/giftia.db --apply
python3 tools/quality_repair.py --db /opt/giftia/data/giftia.db --rollback
```

运行迁移后的新 Store 才具备附加策略表。已有部署应使用下面的完整发布流程，避免手工顺序出错。

发布工具默认只预览。实际发布需要使用已验证、与正式目录分开的候选源码路径：

```bash
sudo python3 /path/to/candidate/deploy/quality_release.py --source /path/to/candidate --repair-memories
sudo python3 /path/to/candidate/deploy/quality_release.py --source /path/to/candidate --repair-memories --apply
```

它保存 `data/releases/quality-时间戳/` 下的代码快照、数据库一致性备份、运行文件快照和修复预览；保留 `.env`、`*.local.toml`。模型配置有任何变化会拒绝执行。健康检查失败时恢复代码与本次记忆策略，不直接覆盖实时数据库。

```bash
sudo python3 /path/to/candidate/deploy/quality_release.py --rollback /opt/giftia/data/releases/quality-时间戳
```

当前剩余边界：

- 自然度仍需用户多轮体验，当前模型会有波动；规则和记忆治理不能保证每轮都理想。
- 网页主回复仍串行、非流式；维护网络已分离，但主模型与工具请求仍可能慢。
- 请求结果默认保留 24 小时/最多 256 条；生成中崩溃且无已落库回复时，不保证自动完成，明确报中断。
- 显示历史仍非跨设备完整同步；推送仍是空载荷加“最近一条消息”，服务接受不等于设备实际显示。
- 每设备订阅按钮、异地备份、语音和 APK 重建不属于本次聊天质量改进。
