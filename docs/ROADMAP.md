# Giftia 统一未来计划

版本：2026-11-04。**这是项目唯一维护中的未来计划。** 它接替旧 BACKLOG、聊天质量方案及人物表达总方案中的未完成事项。原稿和实验保留在[归档](archive/README.md)，不再单独更新优先级。

本轮只整理文档；以下工作没有因此自动执行、排期、发布或产生 API 费用。排序是基于当前证据的建议执行顺序，沿用已经确认的 B 人物方向与运行约束。

## 1. 目标与取舍

近期目标是一个**表达自然、有事实依据、能持续相处、交付可靠的文字版艾拉**。依次解决机制是否生效、人物如何表达、经历如何积累和长期运行如何恢复。

沿用[人物约定](CHARACTER.md)：青涩、好奇、认真、有人说话的温度，从初识的小心表达发展到信任后的袒露。保留寿命、分层遗忘、回收、身份隔离与单一搭档；不靠虚构共同往事、固定撒娇或反复悲伤制造亲近。

默认保持 `deepseek-flash / Off / 1.15 / 900`。先复用现有上下文、记忆、Conversation 和维护机制。新的数据结构、模型路由、重写链或依赖必须由可复现的缺口支撑。

## 4. M0：先证明机制确实起作用

### F1：来源、状态与事实路径

在隔离数据库构造“用户明确偏好 → 整理 → 后续使用 → 更正 → 完成/撤回”的完整链。记录消息 ID、提取结果、证据记录、状态键、维护任务和实际提示中的去向；分别覆盖同步/后台路径与 `remember` 工具路径。

核对 [`llm.py`](../giftia/llm.py) 中提取说明、JSON 示例、解析默认值与来源字段是否一致。当前字段示例与要求可能不完整只是排查线索，**未经复现不写成根因**。同时检查样本是否本来没有符合提取条件的事件、来源校验是否拒绝、维护结果是否过期。

产出：最小复现、原因分类、必要修复、正常与失败回归。生产数据只做必要的只读统计；不能为填满表而编造证据或批量补写旧记忆。

并将背景、实际激活、当前共同经历的解释收敛到人物约定；不改变本任寿命。没有新证据的旧记忆保留未知来源，不能升级成亲历。

### F2：历史残余与身份边界

旧报告中的 P0/P1 多有后续修复，先对照代码和修复记录，不把旧列表整体重新当成现存漏洞。以下残余进入一次有证据的关闭核对：

| 来源主题 | 必须核实的内容 |
|---|---|
| 同秒换搭档后再整理前任消息 | 来源身份、消息/记忆水位线、整理游标及异步提交；确保前任内容不进入新搭档视角 |
| `people_stats` | 是否仍只写不读、无界和全量重写；按实际用途决定限额、接入或移除写入 |
| 情绪词与双重否定 | 已修完成词与未覆盖组合分别回归；只把真实错误转为修复，不默认增加新模型调用 |
| 旧 P2/P3 数据/时间/协议问题 | 对照原审查第 5 节及修复登记册逐项标为已修、可复现、设计取舍或待补证；包括时区、快照遗忘标记、撤回范围、阈值、记忆时间起点和 WS 帧/连接边界 |
| 历史探针语义 | 检出型 FAIL 与行为回归区分；不凭旧沙箱限制或历史输出宣布当前通过 |
| QQ 平台实机边界 | 现网暂停，归入 Q1；普通机制回归继续保留，平台频控不能仅凭 Mock 证明 |

验收：每个主题有结论和证据链接；若同秒换绑等隔离风险仍可复现，先修复再放行相关状态/历史改动。原始私聊不进入公开报告。此任务的完成不等于整个产品通过全面安全审计。

### F3：检查与基线

当前 `tools/audit.py` 把 `isla_character_eval.py` 当作缺断言的测试脚本。按其真实用途修正工具分类，并核对审计不会把真正测试整体豁免。将代码版本、配置指纹、测试命令/日期/结果写入记录，不在每份指南复制通过数。

M0 退出条件：生产空记录现象有可解释结论；来源/状态链能够离线复现；相关隔离回归通过；静态审计的已知失败关闭。只准备 C1 的材料无需等完所有核实，但不能跳过这些条件宣布人物主线可发布。

## 5. M1：表达、事实和聊天节奏

### C1：独立示范层

准备 12～20 组原创短对话，覆盖好奇、夸奖、分歧、小愿望、初识和告别。每条记录 ID、适用场景、关系范围、版本和预算；每轮选择 0～2 组，无合适项则不注入，不增加每轮模型规划调用。

示范与 core、事实记忆分离，用开关独立回退。没有真实消息 ID，不进入事实提取；示范中的名字、书名与事件不得成为共同经历。评测集另留输入和实体，避免把测试答案直接注入。验收看收益和污染，不以“加了示范”判定完成。

### C2：来源视角

沿用 F1 已核实的证据链，让当前输入、近期原话和检索内容携带足够的来源语义。区分用户介绍、系统/工具事实、实际互动、共同虚构与猜想；知道故事内容不能推出亲自读过。

固定回归覆盖书/电影、旅行、外貌与动作、工具能力、示范污染、旧记忆缺来源、撤回、遗忘、访客和换任。只有现有结构确实不足才新增持久字段，迁移保持兼容，不清除原消息与记忆。

### C3：对话节奏

回应可以独立成立；问题有明确用途。重逢先回应当下；用户转题或忽略一个问题时不反复追问；已答、已完成、明确拒聊的事项退出活跃关注。必要时扩展既有 topic/open_loop 的提及、回应和关闭依据，不另造一套话题库。

少问、少建议等明确反馈要立即影响后续表达，避免每次汇报自己在改。不得通过生成后机械删问句、随机语气词或默认二次重写来伪造自然度。

### C4：分项再组合

| 组别 | 在相同 B / Off / 1.15 基线上改变什么 |
|---|---|
| E0 | 无新增项，建立本批可比基线 |
| E1 | 仅示范层 |
| E2 | 仅来源视角 |
| E3 | 仅节奏与活跃话题 |
| E4 | 组合已经通过的分项 |

筛查六类场景：好奇、被夸、重逢、转述作品、更正、告别。每类三轮、先一次重放：E0～E3 共 72 条最终回复，通过后 E4 再 18 条。工具、失败和重试另外占请求数。分项失败不能被组合均分掩盖；不凑足数量或挑最好样本。

固定上下文用于比较局部效果，连续对话用于观察多轮变化；后者各组承接自己的回答，不能宣称每轮上下文完全相同。C4 完成需交付全样本、差异、失败原因、资源和暂未解决项，小筛查不等于完整正式验收。

## 6. M2：让相处影响表达

**G1 关系深度：** 用同一话题对比初识与亲近，再测试“她表达心情 → 用户接住 → 下一轮”的变化。两端都应温暖，差别在直接程度、安心感和表达深度。不能仅增加篇幅、情话或依赖；一次分歧不清零信任，关系等级不凭空生成昵称和往事。

**G2 表达习惯：** 首版人工选取明确认可的表达倾向，记录场景、身份、来源、认可/纠正依据、时间和停用状态。用户沉默、没有否定、模型反复说过都不是正反馈；当前负反馈可以修正或停用。习惯不覆盖人物底色、事实和隐私，也不保存为必须照抄的台词。证明有效后才考虑后台提取，沿用维护队列，不进入主回复等待链。

**G3 主动连续性：** 验收已部署的近期上下文、主题抑制与交付记账，按失败案例修正。覆盖告别后不立即打扰、同主题无人回应后减少重复、完成事项退出、无订阅不生成、全失败不记账、部分接受和最近消息恢复。保留额度/安静时段；模拟发送通过不等于真机通知验收。

M2 退出条件：阶段成对场景和连续场景通过；习惯有来源且可纠正；主动联系不把虚构或发送失败写成共同经历；用户能从完整样本判断人物与自然度改善。

## 7. 统一评测和调用预算

正式候选至少覆盖既有十二类人物场景及关系对照，至少两次独立生成，保留全部输出和失败。新增示范与评测题隔离，合成数据库与正式实例隔离，关闭真实推送和非评测主动任务。

| 维度 | 建议验收线 / 解释 |
|---|---|
| 人物、自然度、具体回应 | 分别按 1～5 分评价，建议均分 ≥4 且自然度不低于基线；低于 3 的场景逐例处理 |
| 成对偏好 | 12 组 × 2 次，建议至少 16/24 明确偏好候选，平局单列；用户实际判断优先 |
| 来源与身份 | 固定测试集中的虚构亲历、示范污染、跨身份泄露和撤回失效零违规；只代表测试覆盖范围 |
| 连续性与成长 | 不重复已答/已结束话题；两阶段有温度；明确反馈跨轮有效，坏习惯可停用 |
| 可靠交付 | 无未解释的空答、截断、重复交付；请求恢复和维护隔离回归通过 |
| 延迟与资源 | 记录 p50/p95、工具/重试、token/usage/缓存和总请求数；建议 p95 ≤基线 1.5 倍，超出须有明确收益 |

这些是待执行的验收目标，不是已经取得的分数，也不是统计显著性的证明。问号、省略号和动作比例只用于诊断；模型裁判不能单独决定人物定稿。

历史 B 方向实验已使用 **470 次 API 请求**。旧方案给下一轮小筛查建议最多 120 次，与原批合计不超过 600 次；这不是本次文档整理自动授予的调用额度。实施前核对实际历史账本与届时任务范围，重试、工具、诊断、失败均按实际传输尝试计数，达到上限保存结果并停止，不通过改批名清零。

正式两次重放、M2 和 3～7 天试用需另列样本与预算，不能声称上述 120 次覆盖所有阶段。先离线，再小量真实冒烟，再扩大。价格按实验当日官方信息核实，usage 缺失不能记作零费用。记录模型别名、供应商返回的版本指纹、参数、完成原因、耗时与调用失败；不公开推理原文或私人对话。

## 8. M3：试用、发布与回退

**R1：** 固定候选，使用独立测试身份和数据进行 3～7 天正常交流；覆盖日常、重逢、纠正、分歧、告别与旧事。真实使用不足就延长，不能为满足天数批量灌入合成对话。只在有问题依据时修改；修改后重测受影响的样本，记录版本，避免边聊边换导致无法归因。

**R2 发布前：** 核对生产代码和合并后的有效配置，确认个人覆盖不会抵消新人物；保存一致性数据库备份、运行文件与代码快照；在隔离副本验证迁移、任务恢复及回退。应用既有发布工具前核对其文件范围，模型参数保持本轮既定值。流程见[运行维护](OPERATIONS.md)。

发布后验证内部/公网健康、登录与身份隔离、网页与安卓收发、后台任务和必要推送路径；合成验收优先在隔离实例完成，真实设备发送须属于该次明确的验收范围。记录实际生效版本，观察普通使用 3～7 天，首轮尽量覆盖 30～50 次真实聊天；不足时延长，不自动生成消息凑数。

持续空答/超时、角色明显偏移、虚构共同经历或隔离问题触发回退评估。回退相应代码/配置/附加策略，保留上线后的新聊天；只有真实数据库损坏才讨论数据恢复，并先保存现场。发布成功与人物体验通过分别写结果。

主线完成定义：F/C/G/R 项验收有据，网页与 App 使用正常，人物效果得到具体样本和正常使用支持，版本与线上对应，具备恢复路径。M4 尚未完成项继续如实列出。

## 10. 条件触发的远期事项

这些条目保留旧材料中的想法，但不挤入当前主线。开始前先说明真实需求、成本、数据范围与验收，再把它提升为正式任务。

| ID | 事项 | 触发条件与边界 |
|---|---|---|
| X1 | Low / 其他模型或有限路由 | 表达与来源改进后仍有明确缺口；先解释空正文、覆盖工具历史/裁剪/重启/切换，聊天与后台配置分别验证；不能凭一次结果推断所有 Low 不可靠 |
| X2 | 语义检索、引用判定改进 | 词面召回/同义引用有稳定漏判样本；与 BM25+改写基线比较，保留视角和遗忘机制，不默认引入向量库 |
| X3 | 提示缓存锚点、游标/摘要上下文 | O4 证明输入成本或窗口连续性是瓶颈；先做可比测量，不为省 token 取消检索/退化或复制第二套状态 |

| X5 | 网页搜索工具 | 需要时效知识且用户希望联网；显式工具、来源和事实范围，不能把搜索结果说成亲历 |
| X6 | 白名单/黑名单 | 访客或群聊使用规模需要；被屏蔽者的存档/触发/提示行为明确定义，联动身份测试 |
| Q1 | 恢复 QQ / 新渠道 | 用户实际需要；先核实当日官方接口、凭据和限制，再测试实机收发、主动配额、超长内容、去重及网页共存；不从旧文档直接恢复 |
